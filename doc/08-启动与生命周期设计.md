# 08 · 启动与生命周期设计

> 定义「秒开 < 200ms」的启动链路、Activity 首帧 Logo → ComposeView 动态注入机制，以及「打开即结算」的唯一时机；并界定前后台生命周期下的行为（0 后台）。
> 前置：阅读 [00](./00-架构与总览设计.md)（架构/主流程）、[01](./01-状态与数值系统设计.md)（settle）、[07](./07-渲染与动画设计.md)（渲染循环暂停/恢复）。

## 1. 启动链路：五阶分阶管线（黑屏 → Logo → 快捷 → 宠物 → 状态环 → 底部 + 后台结算）

- 冷启动：点击图标 → **首帧可见 < 200ms**；首帧 = 纯黑屏上**居中静态 Logo**（App 壳，原生 View、无 Compose）——Activity 容器启动完成，**不是**整个宠物游戏。全局基底纯黑（圆屏与黑边一体，见 06 §4.1；Compose 界面按页叠同心圆渐变主题背景，见 06 §4.2）。
- **分阶启动（用户决策）**：启动是一条**按优先级、数据就绪即揭示**的管线——分步提交任务、**不做全量并发抢线程**；每环节按优先级逐步完成，整体不被最慢项拖慢：
  1. **壳（黑屏进入）**：黑屏 → 屏幕居中静态 Logo；此时 Activity 容器启动完成；
  2. **右侧功能清单**（Compose 首批）：加载**功能菜单数据**（PluginRegistry → 纯 Intent 快捷项，见 05）→ 就绪后**展示屏幕右缘小箭头**（入口可用信号）——不依赖宠物状态；
  3. **宠物游戏**：加载**游戏模型数据**（当前宠素材/切片解码，见 07）→ 就绪后**宠物形象上屏并开始活跃**（FSM + 动画循环）；
  4. **状态记录**：加载**状态记录数据**（SP 快照读取，<1KB）→ 就绪后**顶部状态信息 + 主环一圈状态条**上屏（先按快照现值展示）；
  5. **底部菜单 + 结算**：底部菜单数据就绪 → **展示底部入口条**（上滑操作面板提示）；**日志与离线结算在本步后台异步开始** → settle 完成后主线程一次性 **apply**（`PetStore.save` 写回 + `SessionLog.openWith` 开场段 + 数值层/动作可用性刷新）。
- 全流程仍为毫秒 ~ 数十毫秒级；分阶 ≠ 人为拉长，而是**调度顺序保证**：UI 永不等待结算、快捷功能永不等待宠物。

```
PetActivity.onCreate（壳：黑屏 → 居中 Logo）
 ├─ ① setContentView(ShellView)          // 纯黑底 + 居中静态 Logo（原生 View，无 Compose），<200ms
 ├─ ② 功能菜单数据 → 就绪 → 右缘小箭头    // PluginRegistry→纯 Intent 快捷项，不依赖宠物状态
 ├─ ③ 游戏模型数据（素材/切片解码）→ 宠物形象上屏并活跃
 ├─ ④ 状态记录数据（SP 快照读取）→ 顶部状态 + 一圈状态条（按快照现值）
 └─ ⑤ 底部菜单数据 → 底部入口条
     └─ 后台：日志 + settle(now) → 主线程 apply：save + SessionLog.openWith(开场段) + 数值层刷新
```

- 壳层首帧用普通 View（`ImageView`/静态 drawable），零 Compose 冷启动开销；各阶「就绪即揭示」靠主线程空闲/下一帧分步提交（`doOnNextFrame`/Choreographer），不堆在 onCreate 一条龙。
- **技术选型注**：全局功能实现以 Compose 为主（00 T-19 / ADR-17），壳层首帧的原生 View 是**唯一**既定**必要例外**（首帧 <200ms 硬指标 + 零 Compose 冷启动开销）；②③④⑤ 阶内容一律 Compose。系统能力 Intent（插件拉起 / 系统设置）属系统交互而非 UI 技术，不在此列。除首帧原生 Logo 例外外，新增任何 Compose 外 UI / 渲染技术须先与用户确认。

## 2. BaseActivity 壳与宠物游戏注入（代码要点）

主屏 = `PetActivity : BaseActivity`。**BaseActivity 提供圆屏壳公共能力**，供主屏与后续各独立功能 Activity 复用（见 00 T-16 / 09）：

- **深色圆屏主题**（基底 `bg` #000000；功能页主题背景 = 同心圆渐变、限深色低饱和，06 §4.1/§4.2）与安全区内边距、手势骨架（下拉-状态面板、上滑-操作面板、左滑-功能清单）；
- **五阶管线公共流程**：`showShell()`（黑屏 → 居中 Logo 壳）→ 各阶数据就绪即揭示 → `injectContent`（宠物/面板注入）+ `bootSettle`（第⑤阶：结算后台、完成后 apply）；
- 统一的外部点击/返回收起、生命周期兜底。

```kotlin
abstract class BaseActivity : ComponentActivity() {        // App 壳基类
    protected fun showShell() { /* ① ShellView：纯黑底 + 居中静态 Logo（原生 View，无 Compose） */ }

    protected fun <T> injectContent(
        block: suspend () -> T,                           // ③④ 各阶数据读取（模型 / 状态记录 / SP 快照）
        content: @Composable (T) -> Unit,                 // 宠物形象 / 一圈状态条 Composable
    ) { /* 数据就绪 → setContent → 按阶 addView 揭示（淡入）→ 该阶壳层元素解除 */ }

    protected fun bootSettle() { /* ⑤ 后台 settle + SessionLog 开场 → 主线程 apply：save + 数值层/动作可用性刷新 */ }
}

class PetActivity : BaseActivity() {                      // 宠物游戏 = 主屏 Activity
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        showShell()                                       // ① 黑屏 → 居中静态 Logo（壳层）<200ms
        // ② 功能菜单数据加载（PluginRegistry → 纯 Intent）→ 右缘小箭头——不依赖宠物状态
        injectContent(
            block = { PetStore.load(this) },              // ③④ 游戏模型 + 状态记录数据（SP 快照读取）
            content = { profile ->
                TamagotchiTheme { PetApp(profile) }       // 宠物形象活跃 → 一圈状态条（按快照现值）
            },
        )
        bootSettle()                                      // ⑤ 底部入口条；日志 + 离线结算后台异步 → apply
    }
}
```

> 后续独立功能（便条 / 成就 / 设置…）= 新 `FeatureActivity : BaseActivity`，manifest 注册、`startActivity` 触发；首页不加载其代码，保持纯净（00 §7 / 09 §5）。备注：ComposeView 可用 `addView` 叠加 + `animate alpha` 淡入后移除壳层；若目标 ROM 允许也可直接 `setContentView` 切换。真机验证「首帧切换无黑闪」属待实测项。

## 3. 打开即结算的调用时机（唯一入口）

按 00 §4 与 01 §8：

| 时机 | 动作 |
|---|---|
| 冷启动 onCreate | 五阶管线：黑屏→Logo（壳）→ 功能清单→右缘箭头 → 宠物形象 → 一圈状态条 → 底部入口条；**日志 + 离线结算后台异步**，完成后主线程一次 apply（写回 + SessionLog.openWith 开场段 + 数值层/动作可用性刷新） |
| 热启动 / 从后台回前台 `onResume` | 若距上次 settle > 阈值（如 ≥5s）→ 再 settle(now)；同进程 SessionLog 追加结算节点，不重复开场（04 §3.1） |
| `onPause` | 记录 `onPauseAt`（可并入快照 lastSettledAt 语义，用于下次结算窗口起点）并**停动画循环** |

要点：
- settle 是幂等的：`lastSettledAt` 在每个 settle 后更新；再次 settle 同窗口返回 noOp。
- **不做任何定时器/闹钟**：状态推进只发生在「用户打开」这一次结算，与 0 后台一致（ADR-4）。
- **结算不阻塞 UI 呈现**：宠物形象 / 状态环先按快照现值展示；settle 在第⑤阶后台完成（毫秒级）后 apply 刷新——apply 前动作按现值、apply 后动作可用性随之更新（§1）。
- **右侧快捷功能完全解耦**：只依赖插件注册数据，与宠物/结算无关，自始至终可用（§1）。

## 4. 前后台与渲染循环

| 生命周期 | 行为 |
|---|---|
| `onStart`/`onResume` | 恢复动画 tick（若画面已就绪）+ 结算（若超阈值） |
| `onPause` | 停动画循环（0 CPU）、可落盘当前快照（保险） |
| `onStop` | 释放不必要的 Bitmap 引用（当前宠物保留以便快速恢复） |
| `onDestroy` | 释放 ComposeView/Canvas 引用 |

- 屏幕常亮/抬腕亮屏：不主动请求常亮；依赖系统亮屏，配合 07 §7 的 30s 节能（呼吸+变暗）防烧屏。

## 5. 冷启动性能验证清单

| 检查项 | 目标 | 工具 |
|---|---|---|
| 首帧时间 | < 200ms | Macrobenchmark / `am start -W` |
| 五阶分阶揭示正确 | 黑屏→Logo→右缘箭头→宠物→一圈状态条→底部入口条逐阶可见、无卡顿黑屏 | `am start -W` + 录屏手测 |
| settle 后台不阻塞 | 结算期间 UI 可交互，完成后数值平滑刷新 | 手测 + logcat |
| 冷启动不卡顿 | 无掉帧报错 | logcat Choreographer |
| 动画暂停后 0 后台 CPU | 后台无 wakelock/无 cpu | `adb shell top` / Battery Historian |
| 内存峰值 | < 30MB | Android Studio Profiler |
| 重复冷启 10 次 | 稳定 ≤200ms | 自动化脚本 |

## 6. 待实测 / 风险项

| 项 | 风险 | 对策 |
|---|---|---|
| ROM 差异导致首帧切换黑闪 | 部分安卓 11 手表 | addView 淡入替代直接 setContentView |
| Compose 首次预热开销 | 首帧可能在 Compose init 前 | 首帧 Logo 覆盖直到 Compose 可用 |
| settle 后台结算时长 | 长离线窗口计算耗时 | 分段积分 O(窗口段数) 毫秒级；放后台线程执行，完成后主线程 apply |
| SP 主线程读 | <1KB 毫秒级 | 可接受；若担忧再迁 DataStore 异步 |
