# 07 · 渲染与动画设计

> 定义宠物在中央活动区如何以「4×4 行走图切片」被 Canvas 绘制、动画如何以 4~6FPS 调度，**并新增「情绪/拉伸表现清单」**（在无表情素材的前提下用拉伸/形变表达情绪），以及如何在 <30MB 内存内保证流畅。
> 前置：阅读 [00](./00-架构与总览设计.md)（性能红线）、[02](./02-宠物行为与AI设计.md)（FSM/切片/坐标）、[06](./06-UI与交互设计.md)（布局）。表现层只呈现，不做状态计算。

---

## 1. 素材事实（用户勘误）

- `assets/sprite/<NAME>.png`：**256×256，4×4 网格** = 4 朝向 × 4 帧，单帧 **64×64**。
- **M2.S1 实测（BULBASAUR.png）已钉死：行 = 朝向（0 下 / 1 左 / 2 右 / 3 上）、列 = 帧（0→3 行走循环）**；映射常量表见 `presentation/render/SpriteSheetDecoder.kt`（`Dir.row` / `colOf` / `frameRect`）。若后续个别素材表与此不符，仅改该文件修正。

---

## 2. 三层表现模型（FSM 状态 × 情绪修饰 × 短脚本）

宠物视觉 = 三个正交的叠加层，避免把情绪写死进状态：

```
层1 FSM 基底状态    IDLE/WALKING/EATING/SLEEPING/SICK/SAD/EXCITED
                  → 决定切片帧的用法与基本移动
层2 情绪修饰层      Emotion（拉伸/压缩/抖动/倾斜…，见 §3 清单）
                  → 在基底上叠加 scale/offset/rotate，表达临时情绪
层3 短脚本动画     动作演出（喂食咀嚼、治疗针剂、Zzz 粒子、泡泡…）
                  → 一次性 1~2s 脚本，结束后回到 层1+层2
```

渲染时层 1 决定「切哪张帧」，层 2/3 决定「怎么变形叠加」。

---

## 3. 情绪修饰层清单（Emotion，拉伸/形变为主）

> 设计来源（用户）：无表情素材，用**传统拉伸**呈现情绪：蹦跳（弹动）、沮丧（压扁）等。
> 实现 = 对 `dstRect` 施加 scale/translate/rotate 变换（在 Canvas 上 Save/Load 包裹 drawBitmap），**不修改源图**。

| 情绪 Emotion | 表现 | 变换（建议） | 触发场景 |
|---|---|---|---|
| `HAPPY` 开心 | **蹦跳**：纵向拉伸上弹 | 纵 scale 1.0→1.25 交替，每跳 300ms×2~3 跳 | EXCITED、玩耍后、喂到爱吃的 |
| `SAD` 沮丧 | **压扁**：横向变宽、纵向压矮 | 纵 scale 0.8 + 横 1.2，低频下沉 | SAD、长离线委屈 |
| `ANGRY` 急躁 | 横向轻微抽动 | 横 scale 0.98/1.02 快速抖动 100ms×2 | 饥饿过久、高 temper 特质 |
| `TIRED` 犯困 | 瞌睡点头 | 绕底心 rotate ±4°，800ms 周期 | 深夜仍醒、将入睡 |
| `SICK` 生病 | 微弱战栗 + 变暗 | 纵 scale 抖动 ±2% + tint 灰 | SICK 状态 |
| `CURIOUS` 好奇 | 前倾歪头 | rotate 8° + 下缘平移前探 4px | 随机事件、智力高的探索 |
| `SHY` 害羞/亲昵 | 侧头躲闪 | 偏移 4px + 快速回正 | 抚摸后 |
| `STARTLED` 受惊 | 跳起 | 瞬时纵 scale 1.3 → 回落 | 随机惊吓事件（预留） |

- 每种情绪 = 一个「参数化形变脚本」（amplitude / period / repeat / easing），纯数值可调，不新增状态机逻辑。
- `Emotion` 由 domain 的 `FSMResult.emotionHint` 提供（02 §5），渲染层只按参数播放。

## 4. 渲染管线（一次帧的生成）

```
每帧（约 250ms，4FPS）：
  1. BehaviorFSM.step(now, snapshot) → FSMResult
     { state, dir, frame, pos, emotionHint, bubble }   // domain 纯函数
  2. SpriteRepository.loadFrame(petId, dir, frame)
     → 256×256 Bitmap 取 64×64 子矩形
  3. PetRenderer.draw(canvas)：
     a. 基底层（层1）：按 state 选帧用法
          IDLE     : 首帧 + 呼吸（±2px 纵向，2s 周期）
          WALKING  : dir 切片帧循环 0→3
          EATING   : 低头 + 咀嚼帧复用第 0~1 帧
          SLEEPING : 旋转闭眼遮罩 + Zzz 粒子（3s 一个）
          SICK/SAD : 见层2 Emotion（SICK 基底加 tint）
          EXCITED  : 由 Emotion(HAPPY) 承担弹跳
     b. 情绪层（层2）：按 emotionHint 施加 scale/offset/rotate（§3）
     c. 脚本层（层3）：一次性动作演出（喂食食物包/针剂/Zzz/泡泡）
     d. 按 pos 绘制到活动区（中心化 dstRect）
  4. BubbleLayer 处理气泡（06 §7）
```

- 所有修饰为**程序化小动效**，无 Transition 动画库；FPS 策略：静态 1~2FPS（呼吸），动态 4FPS，交互临时 6FPS（500ms）（T-03）。

---

## 5. 动画调度与节流

- 主循环 `LaunchedEffect + delay(250ms)`；tick 间无变化则跳过重组（invalidate 标记）。
- 气泡等高频 UI 走 Compose 层，不阻塞 Canvas。
- `onPause` 停循环（0 CPU）；`onResume` 恢复并先结算（08）。

---

## 6. 素材加载与内存控制（<30MB）

- 建档/换宠时加载当前宠物 1 张 PNG（≈256KB ARGB_8888）；Bitmap 池仅此 1 张 + 临时缓冲。
- 开档选宠列表：缩略 Bitmap 池 LRU ~12 张，绝不全量解码 1339 张。
- `AssetManager.list("sprite")` 一次取文件名，配合过滤形态后缀（`PIKACHU_9`）。
- 目标 <30MB 余量大。

---

## 7. 性能预算

| 项 | 预算 | 说明 |
|---|---|---|
| 单帧 draw | ≤ 4ms | 一次 drawBitmap + 形变 Save/Load |
| Bitmap 常驻 | 1 张 256×256 ≈ 256KB | + 列表缩略池 |
| 动画调度 | 静态 1~2FPS / 动态 4~6FPS | |
| 重组 | 每 tick 1 次轻量 | Canvas 全量避免大 Compose node |
| 形变开销 | Save/Load + matrix 每次 ≤0.5ms | |

---

## 8. 与 Compose 的关系（边界约定）

- 宠物本体 = Canvas（PetRenderer）；UI 元素（主环/气泡/面板/图标）= Compose 原语（06）。
- `PetRenderer` 接收 FSMResult + 时钟纯绘制；Compose 层定位与调度。
- 全部绘制 / 形变 / 动画均在 **Compose 内完成**（Compose Canvas / Brush / 图形 API）；不引入 Compose 外渲染技术（SurfaceView / OpenGL / 自定义 View 绘制等）——任何新渲染技术引入须先经用户确认（00 T-19 / ADR-17）。

## 9. 待实测 / 风险项

| 项 | 风险 | 对策 |
|---|---|---|
| 朝向顺序 | 已实测钉死（M2.S1） | 常量表 `SpriteSheetDecoder`；M4 行走接入后再反向复核一次 |
| 64×64 放大 | 模糊 | M2.S2 初定 **FilterQuality.None**（近邻像素，复古锐利不糊，render/PetRenderer）；观感不顺则改 MEDIUM——M10.S2 真机定稿 |
| 形变放大边缘 | 拉伸露边 | v0 已落地：中心化 dstRect 占活动区 96% + clip CircleShape 圆遮罩（render/PetRenderer）；形变垫层 M10.S1 |
| 切片循环伪影 | 帧错位 | 行走帧序测试；非行走复用首帧 |
| 常亮烧屏 | — | 30s 无交互仅呼吸+变暗 |
