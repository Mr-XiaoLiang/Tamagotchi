# 10 · 表情与情绪系统设计（2.0）

> 范围：**常驻 Robot 表情**（`grokBot` Compose Library）+ **情绪内核**（domain 纯逻辑）+ **全屏 Robot 互动模式**。
> 本文件只定义设计；步骤、验收与风险跟踪在 `Task.md` §3 的「2.0 段（M18–M19）」。
> 前置事实：顶部异常图标区在 `PetScreen.kt` 603–657（阈值 `LOW_VALUE_WARN = 30f`）；FSM 主循环在 `PetRenderer.PetLivingSprite`（250ms tick）；在线事件循环在 `PetActivity.EntryFlow`（30s）；屏幕量算统一走 `presentation/component/ScreenAdapt.kt`。

---

## 1. 定位：表情是「宠物的脸」，情绪是「宠物的心情」

两个层次，不要混为一谈：

| 层 | 载体 | 归属 | 生命周期 |
|---|---|---|---|
| **情绪（Mood）** | domain 纯状态机 `MoodEngine` | `domain/engine` | 会话内运行：启动 → 应用停止；**不落盘**（D2 已拍板，运行时状态） |
| **表情（Robot）** | `grokBot` 的 `GrokBot` Composable | `presentation` | 与 Composable 同生共死；不可见即不动（Compose 帧驱动） |

**同源原则（D6 已拍板：必须同源，表达同一个状态）**：`MoodEngine` 产出的 `Mood` 同时喂给两处——① Robot 的 `GrokMood`；② 宠物精灵既有的 `Emotion` 形变层（`PetRenderer.EmotionLayer`，M10 已建）。二者**不各算一套**，避免「脸在笑、身子在哭」。

## 2. 呈现基座：`grokBot` 接入约定

### 2.1 依赖

- `settings.gradle.kts` 已 `include(":grokBot")`；`app/build.gradle.kts` 需 `implementation(project(":grokBot"))`（**M18.S1 首个检查点**）。
- `grokBot` 是 Android Library + Compose（`minSdk 23`，app 为 30，允许）。
- 公开 API 面（只用这些，不碰 `internal/`）：`GrokBot` / `GrokBotConfig` / `GrokBotState` / `rememberGrokBotState` / `GrokMood` / `GrokMode` / `GrokShape` / `GrokColor` / `GrokScheme` / `GrokColor.toColor`。

### 2.2 尺寸（用户给定，单点可调）

```kotlin
object RobotTokens {
    const val SIZE_FACTOR = 0.15f           // 相对 min(width, height)；真机校准：0.2 偏大
    // 用法：metrics.minSide * SIZE_FACTOR   // 230dp 圆屏 ≈ 34.5dp

    const val FULL_SIZE_FACTOR = 0.62f      // **全屏态**边长占比；230dp 圆屏 ≈ 142.6dp（r≈71dp）
    // 用法：metrics.minSide * FULL_SIZE_FACTOR
}
```

- 「常驻小表情」与「全屏模式下的底部宠物缩略」**共享同一尺寸常量**，调一处即同步（用户要求，方便调参）。
- 底部缩略点击热区 = 该尺寸（46dp ≥ 30dp 最小热区，符合 06 §8）。
- **全屏态不能铺满**（真机返工，用户反馈「不像 Demo 里那个会蹦跶的小家伙」）：`minSide` 直接当边长会把机器人拉到贴边，且弹跳/旋转/迸发**没有位移余量**（顶到屏缘出血）。取 0.62 后：与主环（r=111dp）留 ≈40dp、与三向把手（r=89dp）留 ≈18dp，四周留白且动得开。

### 2.3 反色配色（用户给定：脸白、眼黑）

```kotlin
GrokBotConfig(

```

> `loginWrap` / `reduceMotion` 只在引擎构造期生效，之后改无效——若两种模式需要不同取值，用**两个 `GrokBotState`**（小图一个、全屏一个），不要试图切配置。

### 2.4 常动与生命周期闸（D4 已拍板：常动）

- **常驻小表情常动**：不做「静态低频」方案。Robot 自带循环动画（呼吸/眨眼/待机），宿主只在需要时切换**待机动作 ↔ 情绪动作**（`state.show(mood)`），或触发一次性动作（`spin` / `bounce` / `burst`）。
- 只在**不可见**时停：`ON_PAUSE` / `ON_STOP`、抽屉面板打开、以及 ROBOT 模式下的小图（已被全屏图取代）→ `state.paused = true`。
- 情绪计算同样遵守既有「被动生成 + 可见才计算」纪律：不在前台不跑情绪 tick。
- 功耗是本次最大的新增风险面（R3）：常动 = 常驻逐帧 Canvas，必须在 M18.S1 粗测、M19 正式走查；若真机不可接受，退路是「可见才动 / 降帧 / 简化形态」，需回到本文件补勘误后调整。

### 2.5 形态选择（D7 已拍板：随性格 / 宠物种类变化，无法判定退回圆形）

- 输入：`petId`（种类）+ `personality`（seed + 六维 traits + flavor）。
- 纯函数 `RobotShapePicker`（放 `presentation/face`，不进 domain —— `GrokShape` 是库枚举，domain 不依赖 UI 库；可 JVM 单测）：
  1. **主判据 = 种类**：`petId` 稳定哈希 → 形状候选。**同一只宠永远同一形状**，不随重启/情绪漂移。
  2. **性格微调**：traits 只在候选邻域内偏移（如 `activity` 高 → 更跳脱的轮廓，沉稳向 → 更敦实的轮廓），不跨类跳变。
  3. **兜底**：候选越界 / 数据缺失 / 无法判定 → `GrokShape.BLOB`（团块，最接近圆形）。
- 形状在建档时即确定，**不随情绪与时间变化**；换宠 / 切回（M15）后随新 `petId` 重算。
- 结果用 `remember(petId)` 缓存，不写 `PetProfile`（与 D2 一致）。

## 3. 情绪内核 `MoodEngine`（domain，纯函数、可单测）

### 3.1 状态集与优先级

初始态 = **SLEEP**（启动即睡，符合用户要求）；离线结算完成后由 `onBoot` 决定真正落点。

| 优先级 | Mood | 判定输入（建议阈值沿用 `LOW_VALUE_WARN=30`） | GrokMood | 宠物 Emotion |
|---|---|---|---|---|
| 1 | SICK | `fsmState == SICK` 或 `health < 30` | SAD | SICK |
| 2 | SLEEPY | `fsmState == SLEEPING` 或夜间作息档 | SLEEPING / DROWSY | TIRED |
| 3 | HUNGRY | `satiation < 30` | CONFUSED | SAD |
| 4 | DIRTY | `hygiene < 30` | SUSPICIOUS | SAD |
| 5 | SAD | `mood < 30` 或 `sadDurationHours` 达档 | SAD | SAD |
| 6 | 瞬态：PLAYFUL / HAPPY / CURIOUS / EXCITED / THINKING | 交互或事件触发，带 `until` 时长 | PLAYFUL / HAPPY / CURIOUS / CELEBRATE / THINKING | HAPPY / CURIOUS |
| 7 | IDLE | 基线 | IDLE | NONE |

规则：**生理/持久态压制瞬态**（饿着的时候被摸也只是 HAPPY 一瞬就回落）；**瞬态到点自动回基线**，不写盘。

### 3.2 驱动方式（沿用 T-被动生成纪律，domain 不主动 emit）

`MoodEngine` 只暴露纯函数，由外层主动拉取：

| 时机 | 调用 | 驱动者 |
|---|---|---|
| 冷启动五阶 reveal 完成 + settle 完成 | `onBoot(now, profile, summary)` → 由 `EndingMood`（M7）+ 属性定初值 | `EntryFlow`（settle 完成回调） |
| 前台节奏 | `update(now, profile)` → 属性漂移/瞬态到期时回落 | `EntryFlow` 前台计时器（建议复用 30s 事件循环旁挂，或独立 10s 情绪 tick；**不新增常驻 Flow**） |
| 动作 / 在线事件 | `onEvent(mood, kind, profile)` → 瞬态覆盖 | `performAction` / 事件循环命中后 |
| 全屏娱乐交互 | `onPlay(mood, gesture, profile)` → 瞬态 + 可选属性微扰 | `PetScreen` 全屏 Robot 手势层 |

**「应用停止时结束」**：情绪只活在组合层 `State` 中，`ON_STOP` 随进程/组合销毁即结束；下次启动重新 `onBoot`。这与 SessionLog 内存语义一致（04 §3.1）。

**M18.S2 落地注记**（实现回填，供后续调参）：

- 三入口签名：`onBoot(now, profile, summary, zoneId)` / `update(now, profile, state, zoneId)` / `onEvent(state, event, profile, now, zoneId)`；`MoodState(base, transient, until)`，`current = transient ?: base` 是给 UI 的唯一出口。
- **压制时长**：硬压制（SICK / SLEEPY / SLEEP）不接瞬态；软压制（HUNGRY / DIRTY / SAD）瞬态压到 `SUPPRESSED_MS = 1.5s`「一瞬」；其余按 `MoodEvent.holdMs`（4~6s），迎接瞬态 `GREET_MS = 6s`。
- **睡眠判定补夜间作息档**（22:00~07:00）：`SettleEngine.integrate` 只落 `SICK/SAD/IDLE`，夜间入睡不会写进 `profile.fsmState`，只按 `fsmState == SLEEPING` 判会让「宠物在睡、表情却是 IDLE」——故 `baseline` 同时认时段，与 FSM 夜间入睡同源。
- **前台推进不新增常驻循环**：`LaunchedEffect(profile)` 属性一变即 `update`；瞬态到期只在「当前确有瞬态」时挂一个一次性 `delay`（到点再 `update`），遵守被动生成与 0 后台 CPU 纪律。

### 3.3 娱乐交互 = 一种正式互动（D3 已拍板：与抚摸 / 玩耍同性质）

**结论**：全屏 Robot 的点击/滑动不是「纯表演」，它与抚摸、玩耍同构 —— 走同一套 `ActionRule` / `PetActions` / 冷却 / 收益递减 / `stats` / `SessionLog` 链路。

- 动作：`PetActions.onAmuse(profile, now, log)`（`mood +2.5` 走特质×边际递减、`sat −0.5`、写 `ACTION_AMUSE` 日志）+ `ActionRule.amuseDenied`（心情 ≥90 不给）/`AMUSE_COOLDOWN_MS = 30s`。
- **M19.S2 落地取舍**：**不加** `ActionType.AMUSE` / `stats.amuse` / `Cooldowns.amuseUntil` —— 逗弄冷却由 UI 在**运行时**节流（`EntryFlow.lastAmuseAt`），与 D2 一致，不动 schema/codec；逗弄不走面板动作集（面板里没有「逗弄」按钮），故无需新增 `ActionType`。
- 数值方向（建议，真机调参）：`mood +小`、`satiation −微`（玩闹消耗），受 `personality` 系数影响；`stats.amuse +1`；写 `ACTION_AMUSE` 日志；**不产生新属性**。
- **两层反馈**（关键手感）：
  1. **表现层每次都给**：点/滑立刻有表情与动效（PLAYFUL / EXCITED / HAPPY…），不受冷却限制——否则连点没反应会很怪。
  2. **属性层受规则限制**：冷却中 / 已到收益上限时不涨属性，可给一句「它玩累了」的气泡（沿用 `ActionDenied` 表达习惯）。
- 与抚摸/玩耍的关系：**同源不同参**（都进 `performAction` 链路），不另开一套数值通道，避免「刷 Robot 就能白嫖心情」。

| 手势（Robot 展示层自己承接） | 表现 | 情绪 |
|---|---|---|
| 单击 | `bounce()` + 粒子 | PLAYFUL / LAUGHING |
| 横向滑动 | `spin()` | EXCITED / CELEBRATE |
| 纵向滑动 | 视差 + `burst()` | HAPPY |
| 长按 | 定格注视 | LISTENING / THINKING |

## 4. 分层模型与手势归属（用户确认的四层）

> 铁律：**手势跟着面板/组件自己走** —— 谁展开谁接管；**收起态天然没有事件**。Robot 的手势属于「Robot 表情展示层」自身，它被收起成缩略表情时，手势随面板一起消失，不需要任何额外的开关或状态判断。L2 只是 OSD 展示层，不接手势。

| 层 | 组成 | 手势职责 |
|---|---|---|
| **L1 顶层** | 三向抽屉手势层（`EdgeBand = 32.dp` 边缘带） | 带内起手 → **消费 down** 并开/拖抽屉；带外 → 不消费、直接放行 |
| **L2 中层** | OSD 状态展示层（主环 / 三向把手 / 气泡 / 揭示 alpha） | **纯展示，不接手势** |
| **L3 中下层** | **收起态**控件：Robot 缩略表情（COMPANION 态顶部）、宝可梦缩略按钮（ROBOT 态底部中央） | 只 `clickable` 切模式；**收起态天然无交互事件** |
| **L4 下层** | **展开态**内容层：宝可梦游走状态层（`PetLivingSprite`）、Robot 表情展示层（全屏 `GrokBot`） | Robot **展开时自己接管**点击 / 滑动 / 长按（`requireUnconsumed = true`，只吃 L1 放行的）；宠物游走层维持既有点击抚摸链路 |

**事件流向**：触摸 → L1（边缘带内即消费并开抽屉；带外放行）→ 展开态的 L4 Robot（命中即娱乐交互）/ L3 缩略控件（命中即切模式）→ 状态变化驱动重绘。

**边缘为什么天然隔离**：Robot 展示层的手势用 `awaitFirstDown(requireUnconsumed = true)`，只接收**未被消费**的 down；边缘带内的 down 已被 L1 消费掉，根本到不了 Robot —— 无需在 Robot 层判矩形。

**落地要点（易踩坑，M19.S2 真机暴露并定案，R6 收口）**：Compose 的 hit-test 是**子节点先于父节点**、**同级后声明者（z 更高）先命中**。
- ❌ **「置顶独立手势层」方案已证伪**：本文件原计划把三向抽屉手势抽成最后声明的全屏手势层 Box（置顶），带内接管、带外「不消费直接放行」。真机实测**面板打开后完全无法操作、无法收起（只剩返回键），顶部表情也点不动**。根因：`awaitPointerEventScope` 在手势块结束时会**把未消费的 change 一并消费掉** —— 置顶层即便带外立刻 `return`，事件也已被吞，下层一个都收不到。已回退。
- ✅ **现行方案（三向手势留在根 `BoxWithConstraints` 的 modifier 上，即父节点）**：它最晚收到事件，此时子节点（面板 / 控件 / 宠物层）都已处理完，它的自动消费不影响任何人。带内起手仍 `down.consume()` + 后续 `change.consume()` 全程接管。
- ✅ **「边缘天然隔离」改由几何保证**：Robot 娱乐手势层只覆盖 `minSide − 2×edgeBand` 的内圈（`PetScreen` 中独立 Box），**边缘带压根不在它的 hit 范围内** —— 不靠先后顺序、也不做矩形规避。
- 附带：`robotPlayGestures(enabled = panel == null && !debugGrid)` —— 面板打开时整层卸载，避免点面板顺带逗到 Robot。

### 4.1 显示模式

```kotlin
enum class FaceMode { COMPANION, ROBOT }   // COMPANION = 宠物游走（现状），ROBOT = 表情全屏
```

- 挂在 `PetScreen` 组合层（**不新开 Activity**）：避免重建 `PetState` / FSM / SessionLog，且便于做尺寸共享与过渡。
- `COMPANION`：宠物游走（现状不变）+ 顶部常驻小表情。
- `ROBOT`：Robot **居中放大但不铺满**（边长 = `minSide × RobotTokens.FULL_SIZE_FACTOR`，见 §2.2）、宠物缩为**静态 pose 帧**图标钉在屏幕底部中央（尺寸 = `RobotTokens.SIZE_FACTOR`，**D5 已拍板：静态，不呼吸不走动**）；**FSM 主循环停**（`livingRunning = false`，省电）。
  - **OSD 不再整体让位**（真机返工）：主环 / 顶向把手 / 右向把手在 ROBOT 下**照常显示**，属性环形进度条全程可读；只有中央游走宠物层退场（`petFactor`），底向把手隐藏（`bottomHandleFactor`，该位置由底部宠物缩略接管，避免叠压）。
  - **底部缩略位置不能取 `handleR`**（真机返工）：`handleR` = 89dp 整个按钮泡在**底向边缘热区带**（32dp，即 y > 83dp）里，点它会同时拖开底部操作面板，表现为「点回收不了宠物、倒先把面板拖出来了」。改由 `ScreenMetrics.robotThumbOffsetY()` 统一算出安全位：`radius − edgeBand − 边长/2 − THUMB_EDGE_GAP`（230dp 屏 ≈ 61.75dp，下沿 79dp < 83dp）。
  - **回 COMPANION 必重启行走循环**：ROBOT 期间 `livingRunning = false`，`PetLivingSprite` 的主循环协程是**整体退出**的；除了依赖 `running` 翻转，再给主循环加一个 `wakeKey = faceMode` 锚点，确保每次切回行走态必定重新起跑（防「切回来宠物定格不动」）。
- 切换入口：点顶部小表情 → ROBOT；点底部宠物缩略 → COMPANION。
- 返回键：ROBOT 下返回 → COMPANION，不退出 App（`BackHandler`）。

### 4.2 状态归属

`FaceMode` 与 `Mood` 放在组合层（`PetScreen`/`EntryFlow` 之间的 `remember` state 或 ViewModel 级 holder），**不进 `PetProfile`**（除非 §6-D2 拍板为落盘）。

### 4.3 具体分工与优先级

- **手势随面板走**：Robot 展开（ROBOT 态）→ L4 展示层自带手势接管；Robot 收起（COMPANION 态）→ 只剩 L3 缩略表情的 `clickable`，交互事件**随面板一起不存在**，无需判断 `FaceMode`。
- **L4 Robot 手势语义**：单击 → `bounce()` + PLAYFUL；横滑 → `spin()` + EXCITED；纵滑 → `burst()` + HAPPY；长按 → LISTENING / THINKING。
- **L3 缩略控件**：落点在「顶部 Robot 缩略 / 底部宠物缩略」上 = 切模式，不是娱乐交互（两者互斥由层级天然保证：展开态没有缩略，收起态没有全屏手势）。
- **气泡优先级**：`GreetingBubble`（全屏 `clickable`）展示期间吃掉点击，消失后再响应 Robot 交互。**M20 落地**：气泡经 `onVisibleChange` 上报 `bubbleVisible`，Robot 手势层 `enabled` 含 `!bubbleVisible`；且宿主手势用 `requireUnconsumed = true`，被气泡/缩略消费掉的 down 到不了 Robot（依据：库内 `pointerInput` 只记录坐标、从不 consume）。
- **库内眼随手指**：`GrokBot` 自带 `pointerInput` 属它自己的表现层，与宿主手势并存、不参与业务判定（真机验证共存，R2）。
