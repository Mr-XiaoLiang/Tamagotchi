# 05 · 原生插件管理系统

> 「原生功能清单」（右滑列表）的本质是一套**插件化架构**：把「打开某个 App」「打开系统设置页」「执行一个本地动作（如手电筒、闹钟提醒）」「通讯（呼叫）」抽象成统一插件，模块化注册、展示与触发。本期重点在插件模型、注册表、右滑清单 UI 与 Intent 容错。
> 本文为独立子系统设计，与主屏信息架构的接入见 [06-UI与交互设计.md](./06-UI与交互设计.md)；「呼叫/通讯类」功能对拓麻歌子 10 功能的映射见 [09-功能系统与扩展路线.md](./09-功能系统与扩展路线.md)。

---

## 1. 设计目标

- 主屏右滑 → 展开原生功能清单（插件列表）。
- 插件**不限于「打开某 App」**：涵盖系统动作、设置页、自定义能力，均可模块化接入。
- 极低侵入：新增一个插件 = 新增一条注册表记录（代码或配置），无需改列表 UI。
- 全部触发走 **Intent 白名单 + try-catch 容错**，包名不存在时给轻提醒，不崩溃。

---

## 2. 插件抽象模型

```kotlin
enum class PluginTriggerType {
    LAUNCH_APP,      // 拉起第三方 App（action=MAIN, category=LAUNCHER）
    OPEN_SETTINGS,   // 打开系统设置页（如 wifi/bt/bluetooth）
    LOCAL_ACTION,    // 本地执行的动作（如：启动手电筒、开勿扰、临时计时）
}

data class PluginSpec(
    val id: String,              // 稳定 id："launch.wechat" / "action.torch"
    val name: String,            // 显示名（可多语言 key）
    val iconRes: Int,            // 图标 drawable（菜单用）
    val type: PluginTriggerType,
    val intent: Intent?,         // LAUNCH_APP / OPEN_SETTINGS 使用
    val action: (() -> Unit)?,   // LOCAL_ACTION 使用（本地回调）
    val sort: Int = 0,           // 默认排序权重
    val enabled: Boolean = true,
)
```

- **`PluginRegistry`**（domain）持有全部插件列表 + 读取用户排序/隐藏偏好（SP，见 [01 §9](./01-状态与数值系统设计.md) `plugins` 字段）。
- **`PluginExecutor`**（data 层）负责真正触发：构造 Intent → `try { startActivity } catch { 轻提醒 Toast/Bubble「没有安装该应用」 }`。

## 3. 注册表与默认插件表

默认注册（初版建议）：

| id | 名称 | 类型 | 说明 |
|---|---|---|---|
| `launch.wechat` | 微信 | LAUNCH_APP | 白名单：com.tencent.mm |
| `launch.alipay` | 支付宝 | LAUNCH_APP | 白名单：com.eg.android.AlipayGphone |
| `launch.health` | 健康 | LAUNCH_APP | 白名单：com.sec.android.app.shealth 等（按设备） |
| `launch.phone` | 电话/呼叫 | LAUNCH_APP | 通讯类（映射拓麻歌子「呼叫」）：`ACTION_DIAL` 或拨号盘，白名单按设备 |
| `settings.wifi` | Wi-Fi | OPEN_SETTINGS | `Settings.Panel.ACTION_WIFI` |
| `settings.bluetooth` | 蓝牙 | OPEN_SETTINGS | `Settings.Panel.ACTION_BLUETOOTH` |
| `settings.battery` | 电量 | OPEN_SETTINGS | `Settings.ACTION_BATTERY_SAVER_SETTINGS` |
| `action.torch` | 手电筒 | LOCAL_ACTION | Camera2 闪光灯（**需相机权限，默认关闭待权限流**） |
| `action.dnd` | 勿扰 | LOCAL_ACTION | 切换 `NotificationManager` 勿扰模式 |
| `action.timer` | 计时器 | LOCAL_ACTION | 本地 Snackbar/Toast 简单计时提示（示例扩展点） |

> 白名单**不内置全量包名列表**，而是每个 LAUNCH_APP 插件带 `expectedPackages[]`，触发时用 `packageManager.getLaunchIntentForPackage` 依序探测可用者。

## 4. 右滑清单 UI（列表页）

> 详细布局见 [06-UI与交互设计.md](./06-UI与交互设计.md)，此处只定插件侧交互。

- 右滑从屏幕右缘进入（EdgeSwipe），**胶囊纵向列表**（RoundList + 胶囊条目，表盘适配旋转表冠 + 触屏；样式见 06 §8.3）。
- 每条 = **胶囊**：有 icon 时 icon 居胶囊左 + 名称，无 icon 直接文字，右侧可带小箭头；**可触发 → 实心胶囊**（点击 = 触发）；**暂不可触发 → 空心胶囊**（如 LAUNCH_APP 目标均未安装：仍展示但描边不可点，可长按隐藏/移除）。
- 长按（或顶栏设置入口）→ 编辑模式：排序 / 隐藏插件 / 恢复默认。
- 运行期触发失败（实心胶囊但未拉起成功）反馈：Bubble（「没找到微信」）+ 抖动图标，不弹系统错误。

## 5. Intent 白名单与容错规范

1. **只允许注册表中声明过的插件发起 Intent**，杜绝任意包名唤起（安全 + 可控）。
2. 触发统一走 `PluginExecutor.execute(spec)`：

```
execute(spec):
  when (spec.type) {
    LAUNCH_APP   -> for (pkg in spec.expectedPackages) {
                      getLaunchIntentForPackage(pkg)?.let { startActivity(it); return }
                    }  // 全部失败 → notFound(spec)
    OPEN_SETTINGS -> try { startActivity(spec.intent) } catch { notFound(spec) }
    LOCAL_ACTION -> spec.action?.invoke()
  }

notFound(spec): 触发「插件未安装」Bubble/Toast（不是 crash）
```

3. 前台启动第三方 App 涉及 `RECENT_APPS`/返回栈策略：用 `startActivity` + 默认 FLAG 即可，跨 App 返回依赖系统（真机验证：部分手表 ROM 需 `FLAG_ACTIVITY_NEW_TASK`，属待实测项）。

## 6. 扩展点（新增插件接入规范）

- 新增一个插件 = 在 `PluginRegistry.defaults` 加一行（代码注册），或未来改为 assets json 声明式注册。
- **LOCAL_ACTION 是天然扩展位**：可新增「报时」「倒计时」「开勿扰」「手电筒」等本地能力，无需额外 App。
- 权限类插件（相机/位置等）单独标记 `permissionRequired`，运行时权限流统一由 PluginExecutor 前置检查，未授权则触发系统授权请求而非直接失败。

---

## 7. 与主应用交互边界

- 插件清单是**并行第二屏**（与宠物主屏并列），互不干扰（用户决策）。
- 宠物主屏可通过「右侧左滑箭头」或「边缘 hint 区」进入；返回靠左滑/系统返回。
- 插件触发不影响宠物状态计算（不写入属性/FSM），仅做系统动作——保持「陪伴主玩法」与「工具功能」解耦。
