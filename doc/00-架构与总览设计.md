## 2. 产品与技术定位速览

- **形态**：运行于 Android 11+（API 30）圆形表盘（非标准 Wear OS 壳）的独立 App，横竖皆可，以圆形为主视觉。
- **玩法**：单宠陪伴。开档从 1339 张宝可梦行走图中任选一只，之后形态固定、无进化；一切表现由当前属性 + 状态即时驱动。
- **性能红线**：冷启动首帧 < 200ms；常驻内存 < 30MB；动画 4~6 FPS；后台 0 CPU（无 Service / 无 AlarmManager）。

## 3. 四层架构与模块边界

依赖方向：`presentation → domain ← data`，`presentation / domain / data` 均单向依赖 `core`（通用类型），**不允许反向依赖**。

```
┌─────────────────────────────────────────────────────────────┐
│  presentation（表现层，Compose / Canvas，Android 依赖最重）     │
│  · base: BaseActivity(App 壳/深色基底/安全区/手势骨架，见 08)  │
│  · PetActivity(宠物游戏主屏)、ControlPanel、PluginList、Status  │
│  · component: RoundSafe 圆屏组件库（RoundSheet/RoundList/Pill…，06§8.2/8.3）│
│  · ui: RingProgressBar / BubbleView；PetRenderer(切片，见 07)   │
├─────────────────────────────────────────────────────────────┤
│  domain（纯 Kotlin，无 Android import，可单测）                 │
│  · SettleEngine   —— settle(now) 打开即结算（见 01）           │
│  · BehaviorFSM    —— 状态机 + 随机决策（见 02）                │
│  · PersonalityGenerator —— 性格生成（见 02）                   │
│  · EventEngine    —— 在线随机事件（见 03）                      │
│  · OfflineTimelineBuilder —— 离线时间线回放生成器（见 03 §7）   │
│  · SessionLog     —— 会话日志（纯内存、进程内，见 04）          │
│  · ActionRule     —— 动作规则与冷却（含食物类型，见 01/09）     │
│  · PluginRegistry —— 插件注册表（见 05）                       │
│  · Model: Pet / PetState / Attribute 等不可变值对象             │
├─────────────────────────────────────────────────────────────┤
│  data（持久化 / 素材 / 系统能力适配）                            │
│  · PetStore(SP 快照，见 01) —— 唯一持久化点                     │
│  · SpriteRepository —— assets/sprite 按名索引，仅解码当前宠物    │
│  · PluginExecutor —— Intent 白名单 + 容错（见 05）             │
│  · Clock —— 时间源抽象（注入以便测试）                          │
├─────────────────────────────────────────────────────────────┤
│  core（跨层）：TimePoint、AttributeId、PetId、枚举常量等        │
└─────────────────────────────────────────────────────────────┘
```

设计要点：
1. **domain 零 Android 依赖**，是后续单测的根；时间、持久化均通过接口/注入隔离。
2. **data 的 PetStore 只存「快照 + 上次结算时间戳」**，不做任何计算，计算全在 domain。
3. SpriteRepository 只按需解码**当前选中宠物的一张 PNG**（约 256×256），启动不遍历 1339 个文件元数据（仅首次建档时列出可选列表）。

## 4. 核心主流程：打开即结算

> 「打开即结算」是全游戏的状态演进唯一入口。App 的任何一次可见启动都会执行，且**仅在此时**执行。

```
用户点击图标/回到前台
        │
        ▼
① 黑屏 → 居中静态 Logo（App 壳，原生 View、无 Compose，<200ms）
   纯黑基底（06 §4.1/§4.2 页面渐变背景）——Activity 容器启动完成
        │  （Compose 启动）
        ▼
② 加载功能菜单数据 → 就绪 → 右缘小箭头
   PluginRegistry → 纯 Intent 快捷项（见 05）；不依赖宠物状态
        │
        ▼
③ 加载游戏模型数据（素材/切片解码，07）→ 宠物形象上屏并活跃
        │
        ▼
④ 加载状态记录数据（SP 快照读取）→ 顶部状态 + 一圈状态条（按快照现值）
        │
        ▼
⑤ 底部菜单数据 → 底部入口条（上滑操作面板提示）
   │  后台异步：日志 + 离线结算 settle(now)（domain，见 01 §8）
   │    短离线(<20min) → 快速积分扣减
   │    长离线(≥20min) → 事件化时间线：
   │       · 生理消耗骨架事件铺排 N 片（时间片带抖动节奏）承载自然衰减
   │       · 突发扰动事件按 traits 概率插入（正负净值受控）
   │       · 应用封顶、绝不致死；判定 SICK / SAD / SLEEPING
   │       · 产出 SettlementSummary：回放剧 + 聚合变化 + 结尾基调
   ▼
  主线程一次性 apply（唯一状态写入点）：
    PetStore.save() 写回 + SessionLog.openWith(开场段) + 数值层/动作可用性刷新
```

关键规则：
- **App 在后台/进程被杀期间不做任何事**（0 后台由「没有任何定时器/Service」保证）。
- settle 是**幂等**的：以 `lastSettledAt → now` 为窗口；完成后立刻更新 lastSettledAt，重复调用同一 now 不会二次扣减。离线回放剧是**纯派生结果**（快照 + 以时间为种随机），是否展示不影响快照终态；会话日志不落盘，每次启动由新一次结算重新开场（见 04 §3.1）。
- 启动 = **五阶管线**（壳/Logo → 快捷箭头 → 宠物形象 → 一圈状态条 → 底部入口条 + 后台结算，见 08 §1）：**数据就绪即揭示、settle 不阻塞 UI**——宠物/状态环先按快照现值展示，结算后台完成后 apply 刷新；右侧快捷清单全程解耦。
- 全应用只有这一个「状态写入点」，避免属性在多处被改导致的不一致。

## 6. 决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|---|---|
| ADR-1 | 单宠开档任选其一；换宠 = 重开档（M1–M10 覆盖写；M15 起升级为「换宠归档 + 快照切换」，见 Task.md M15 / 04 §3.3 / 09 §5.5） | 专注陪伴；素材天然支持任意选择；换宠归档仍是快照存取、不落日志 |
| ADR-2 | 形态固定无成长/进化 | 用户选定「纯维持」，降低复杂度 |
| ADR-3 | 纯状态驱动，无亲密度/记忆 | 表现完全由当前三属性决定，最轻量 |
| ADR-4 | 取消 AlarmManager，打开即结算 | 0 后台 + 简单可靠，唯一状态入口 |
| ADR-5 | 离线封顶不致死 | 避免「一夜没管就死」的劝退体验 |
| ADR-6 | SP 存快照：M1–M10 单键当前宠；M15 起扩展多档（当前档 + 墓碑档） | 数据量极小（< 1KB）；多档仍在 SP、仍是快照 |
| ADR-7 | 素材按 4×4 行走图切片渲染 | 素材实际为行走图拼合表，勘误确认 |
| ADR-8 | 手势：底部上滑=操作面板；右侧左滑=原生功能清单 | 圆形表盘信息架构最简拆分 |
| ADR-9 | 性能红线不变（秒开/30MB/4~6FPS） | 与 README 一致 |
| ADR-10 | 离线结算事件化：长离线生成「离线时间线回放剧」（生理消耗骨架 + 突发扰动，trait 调制节奏），写入**内存会话日志开场段**而非持久化 | 让每次数值消减有过程、可阅读，强化陪伴叙事（见 03 §7） |
| ADR-11 | 事件日志统一为进程内**内存会话日志（SessionLog）**：启动 settle 铺开场段（离线回放 + SETTLE 聚合），在线事件追加进同一时间线；退出即清空、不持久化，快照是唯一持久化点 | 用户决策：最简数据面，无存储/迁移/历史包袱；每次启动以离线结算重新开场（见 04 §3） |
| ADR-12 | 分阶启动 + 功能 Activity 化：五阶管线（壳→快捷→宠物→状态环→底部，结算后台 apply）；后续功能以独立 Activity（: BaseActivity）追加 | 秒开且快捷功能第一时间可用；隔离加载、首页纯净，避免主屏膨胀（见 08 §1/§2） |
| ADR-13 | 状态面板统一「顶部下拉」形态：下拉 / 屏顶状态图标 / 操作面板「状态」三入口同一面板；点击菜单「状态」= 收起下、展开上 | 对齐系统下拉的潜意识交互，行为一致（见 06 §3/§5） |
| ADR-14 | 跨会话里程碑统计用 SP 整数计数 `stats`（动作命中 +1），不为此持久化日志/档案 | 日志仅内存前提下，计数即可达成里程碑效果且成本最低（见 04 §3.3 / 01 §9） |
| ADR-15 | 圆屏界面标准组件化（RoundSafe 组件库），新增面板/清单/文本必须复用 | 圆形屏边缘大裁切，列表/文本不可按手机方式展示；组件化统一安全区处理、支撑扩展（见 06 §8.2） |
| ADR-16 | 界面基线：深色一体基调（基底纯黑隐藏黑边）+ 同心圆渐变主题背景区分功能页（只许深色基调、屏缘禁高对比截断）+ 统一主题色 Accent（集中 Token，禁止自造色）+ 胶囊两级（实心=可点 / 空心=不可点，类别色可覆写背景）+ 语义色莫奈低饱和 | 一体观感、可点性一眼自明、扩展即复用胶囊（见 06 §4.1/§4.2/§8.3） |
| ADR-17 | 技术主选型 = Compose 为主 + 官方组件优先 + 官方适配标准：功能 UI/动画/渲染一律 Compose（Compose Canvas / Brush / 图形 API）；非必要不引入 Compose 外技术，任何引入先与用户确认（**唯一必要例外：首帧原生 Logo**；系统能力 Intent / 设置属系统交互而非 UI 技术，不归 Compose 主选型管，不列为例外）；UI/组件优先 Wear Compose Material3 与 AndroidX 官方，屏幕兼容遵循官方 Wear UI 建议 | 代码量最小、维护简单；官方组件免费获得无障碍/旋转/系统字体缩放适配；避免碎片化自造组件与 Compose 外渲染栈（见 07 §8、08 §1） |

## 7. 建议的代码包结构（映射到四层）

```
com.lollipop.tamagotchi
├── core/                 # 值对象、常量、枚举（core）
├── domain/
│   ├── model/            # Pet, PetState, Attribute, EventLog 等
│   ├── log/              # SessionLog, SessionEntry（内存会话日志，见 04）
│   ├── engine/           # SettleEngine, BehaviorFSM, EventEngine

│   └── plugin/           # PluginSpec, PluginRegistry
├── data/
│   ├── store/            # PetStore(SP)——唯一持久化点（见 01 §9）
│   ├── sprite/           # SpriteRepository
│   ├── plugin/           # PluginExecutor(Intent 适配)
│   └── time/             # Clock 实现
└── presentation/
    ├── base/             # BaseActivity（圆屏壳：主题/安全区/手势骨架/首帧→注入，见 08）
    ├── screen/           # PetActivity(主屏宠物游戏) + 各 overlay；未来 FeatureActivity 独立子包
    ├── component/        # RoundSafe 圆屏组件库：RoundSheet/RoundList/PillItem/RoundText/EdgeFade（06 §8.2/§8.3）
```
