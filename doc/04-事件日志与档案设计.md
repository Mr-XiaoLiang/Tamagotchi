# 04 · 事件日志与档案设计

> **v2（用户决策）**：事件日志**只在内存、不持久化**——不写 SP、不落盘，进程退出即清空。它是一条**会话时间线**：启动的离线结算先铺出开场段（离线回放剧逐条 + 一条 SETTLE 聚合），在线期间的动作/事件/状态切换持续追加到同一份列表；下次启动由新一次结算重新开场。持久化的唯一内容仍是快照（见 [01 §9](./01-状态与数值系统设计.md)）。

> 事件日志系统记录「这次上线宠物和你之间发生了什么」——纯状态驱动里承载**开场叙事与陪伴感**的关键基础设施：它本身不参与状态计算，只做忠实记录与复盘展示。
> 前置：阅读 [01](./01-状态与数值系统设计.md)（属性/结算）、[03](./03-随机事件生成系统.md)（事件写入来源）。

---

## 1. 日志要解决什么

1. **开场叙事**：打开 App 先执行离线结算，长离线的回放剧 + SETTLE 聚合铺出**本会话第一段记录**，让「在你离开期间发生了…」有据可依（迎接反馈见 §5）。
2. **陪伴可见**：本会话里每次喂食/抚摸/宠物状态变化都落在同一条时间线上，随时可回看（会话回顾见 §4）。
3. **跨会话不做**：退出即清空、不持久化——昨天喂过几次、上周发生了什么，日志不记录也不承诺（这是用户决策：最简数据面）。跨会话累计走 §3.3 `stats` 计数；换宠时刻的「电子墓碑」以**快照存取**承载（§3.3 / Task.md M15），不落日志。

> 注意边界：**日志不驱动状态**。它是「状态变更的旁路记录」，与 settle/FSM 并行写入，只读不回放（避免复杂化）。
>
> **统一为一条会话时间线（不再是「持久日志 + 瞬态回放」两套）**：
> - 每个应用进程持有一份内存日志 `SessionLog`，生命周期 = 一次会话；
> - 启动：`settle(now)` 产出 `SettlementSummary` → `openWith(...)` 铺开场段（长离线回放剧逐条 + 一条 `SETTLE` 聚合，见 [03 §7](./03-随机事件生成系统.md) / [01 §8](./01-状态与数值系统设计.md)）；
> - 运行：在线动作 / 随机事件 / 状态切换按 ts **追加**进同一份列表；
> - 退出：进程结束即清空，不写 SP / 文件；下次启动由新一次结算重新开场。

## 2. 在线条目结构（EventLog）

> 会话时间线由三类条目组成（见 §7）：`SettleEntry`（结算聚合锚点）/ `ReplayEntry`（离线回放开场）/ `LiveEntry`（内含本节 EventLog）。本节定义 **EventLog**——在线期间由动作/事件/状态切换产生的条目。

| 字段 | 类型 | 说明 |
|---|---|---|
| `ts` | Long | epoch millis |
| `type` | enum | `ACTION_FEED` / `ACTION_PLAY` / `ACTION_PET` / `ACTION_HEAL` / `RANDOM_EVENT` / `STATE_CHANGE` / `WAKE`（扩展 `ACTION_CLEAN` / `ACTION_STUDY` 等随 M11 / M12 追加；结算聚合由 `SettleEntry` 表达，不入 EventLog） |
| `refId` | String? | 关联 id（事件 id、动作 id 等） |
| `beforeAttrs` | dict | 记录前**全部可变属性**快照：sat / mood / health / knowledge / hygiene（按 01 §1.3 属性注册表驱动） |
| `deltaAttrs` | dict | 本次各属性变化量（同注册表键） |
| `state` | PetState | 事件发生时状态 |
| `note` | String? | 可选补充（气泡 key、食物类型/玩具等备注） |

示例：

```json
{
  "ts": 1725205000123,
  "type": "ACTION_FEED",
  "refId": "feed",
  "food": "energy_meal",
  "beforeAttrs": { "sat": 34, "mood": 72, "health": 88, "knowledge": 12, "hygiene": 45 },
  "deltaAttrs": { "sat": 40, "mood": 0, "health": 0, "knowledge": 0, "hygiene": -4 },
  "state": "WALKING",
  "note": "bubble.feed_yum"
}
```

## 3. 存储与上限策略

### 3.1 本期：内存会话日志（进程内，不持久化）

- **无 SP 键、无文件**：日志不落盘，进程退出即清空；持久层只有 PetStore 快照（[01 §9](./01-状态与数值系统设计.md)），职责彻底分离。
- 归属：domain 的 `SessionLog`（纯内存、纯 Kotlin、可单测），由应用进程持有并注入（见 00 模块表）。
- **开场注入**：启动 `settle(now)` 后调用 `openWith(summary)`：
  - 长离线（≥20min）：回放剧 `OfflineEvent` 逐条入列（ts = 离线期各时刻）成为**开场段**，末尾再补一条 `SETTLE` 聚合（ts = now，note = 结尾基调 EndingMood）；
  - 短离线：仅一条 `SETTLE` 聚合。
  - 离线剧情因此是日志的一部分而非独立瞬态物——打开即可看到一条从你上次离开延续到现在的连续时间线。
- **同进程再次结算**（热启动 / 后台回前台超阈值）：SessionLog 已存在则只**追加一条新的 `SettleEntry`**（短离线无回放），不重复铺开场段——开场段只在进程新建时生成（见 08）。
- **在线追加**：动作 / 随机事件 / 状态切换以 §2 的 `EventLog` 形态 `append`（ts ≥ now），追加进同一份列表。
- 按需冗余：不记每个属性 tick（4FPS 会爆量）。**只在事件/动作/结算/状态切换时记录**。
- 软上限：单会话至多保留 **1000 条**（覆盖 48 条回放开场上限 + 长时间在线陪伴）；超出丢弃最旧，纯防御、不落盘。

### 3.2 内存与性能

- 单条 ≈ 0.2~0.4KB → 1000 条约 300KB 级，远低于 30MB 红线。
- 无 SP 写、无磁盘 IO：事件日志不产生持久化写放大，与 T-01 秒开一致。
- 退出即清空，不需要容量/存储空间治理——比任何持久化方案都省心。

### 3.3 跨会话统计 = SP 整数计数（里程碑）；换宠墓碑 = 快照存取（M15）

- **里程碑计数（本期即可预留，推荐位）**：若要「喂了 N 次 / 治好第 1 次病 / 共处 N 天」这类**跨会话累计**，**不需要持久日志**——在 PetStore 快照里加一组 **SP 整数计数 `stats`**（动作/事件命中时 `+1`，见 [01 §9](./01-状态与数值系统设计.md)），打开时按计数判定里程碑文案即可。**计数效果等同日志、成本远低**——这是「日志只在内存」决策下跨会话统计的唯一落点。
- **语义边界**：本 §4 的「会话回顾」仍只覆盖本次会话；**跨会话里程碑由 SP `stats` 承接**（不是日志、不是档案）。
- **换宠墓碑（已排 Task.md M15，仍是快照）**：「宠物图鉴 / 纪念册 / 换宠存档」这类历史，**本质不是日志**——是把换宠时刻的**最终快照**序列化保存（电子墓碑），并支持**快照切换**（切回继续养）。因此在 PetStore 上把「单键当前档」扩展为「当前档 + 墓碑档」即可（schema v3，含 v2 迁移，见 [01 §9](./01-状态与数值系统设计.md) / Task.md M15）；**不上日志、不改 §4 的「回顾只在内存」**。
- M1–M10 不实现墓碑（换宠=覆盖写重开档）；04 的事件结构保持版本化字段，避免 M15 迁移成本。

## 4. 会话回顾玩法（本次陪伴小结）

设计：会话日志本身就是一条从离线结算开始、按时间连续的时间线，随时可回看本次上线期间的记录：

- 「你离开了 2 小时——饿着肚子等了 3 回、被雷声吓醒 1 次，后来睡着啦」
- 「这次见面：喂了 3 次、摸了摸 5 次、玩了一场，谢谢你」
- 「上次见到你是 2 小时前」（由快照 `lastSettledAt` 推算，非日志）

数据来源：
- 开场段文本 = `SettlementSummary`（离线时长 + 回放剧统计 + 结尾基调 EndingMood）；
- 在线段文本 = `SessionLog` 按 type 聚合统计 / 按时间倒序取关键记录；
- 不新增状态：只读内存日志。

> 这是低成本高陪伴感的呈现，且完全基于会话日志，不破坏纯状态驱动。
>
> **语义边界**：回顾**只覆盖本次会话**。「这次喂了几次」来自本会话 SessionLog；跨会话的累计（喂过 N 次 / 共处 N 天）**不可从日志回溯**——这是「日志不持久化」决策的直接结果（§1 / §3.1）。需要这类**里程碑统计**时走 SP 整数计数 `stats`（§3.3），而不是持久化日志。

## 5. 迎接反馈（打开 App 时的差异化开场）

「迎接反馈」是**结算 apply 后**（00/01 主流程第⑤阶：离线结算在后台完成后由主线程一次性应用）触发的一次性表现层事件——此时数值层已刷新、会话日志开场段已就绪；数据来自**本次结算摘要（SettlementSummary）+ 会话日志开场段**——离线时长 / 结尾基调 / 回放剧都在手上，无需跨会话历史：

| 离线时长 | 反馈 | 依据 |
|---|---|---|
| < 10min | 普通招呼「回来啦」 | 无离线累积 |
| 10min~2h | 撒娇「你去哪儿了」 | 短离线 |
| 2h~6h | 有点委屈「等你好久了」 | 中离线 |
| 6h~24h | 委屈 + SAD 倾向表现（若 mood 低） | 长离线 |
| > 24h | 病恹恹/大哭气泡「我以为你不要我了」（若触发 SICK） | 超长离线 + 01 §8 |

实现：读取 `offlineDuration`（结算摘要提供）→ 匹配气泡 key 池（同 key 多文本按权重选）→ 由 [07](./07-渲染与动画设计.md) 的 BubbleView 展示。此反馈**优先于**普通在线事件，但不改写状态。

> **增强（长离线）**：离线 ≥20min 时有离线时间线，开场语气由**结尾基调 `EndingMood`**（[03 §7.6](./03-随机事件生成系统.md)）修正——不再只按时长分档：睡得香→慵懒满足「睡了好久，梦到你了」；饿趴→NEEDY 乞食开场；受凉→SICKLY 病恹恹；若恰好结局是自娱自乐→JOYFUL 的意外惊喜。短离线（无时间线）仍按上表时长档位。

## 6. 事件日志与数据来源闭环图

```
[启动进程]
  ▼
[01 settle(now)] ── 产出 SettlementSummary（离线回放剧 / 聚合变化 / 结尾基调）
  │   短离线(<20min)：无回放段
  ▼
[SessionLog.openWith(summary)]            ← 内存，仅本次会话（§3.1）
  │   长离线：回放剧 OfflineEvent 逐条入列（ts∈离线期）→ 开场段
  │   一律再追加一条 SETTLE 聚合（ts=now, note=EndingMood）
  ├─► 迎接反馈气泡（§5：offlineDuration + endingMood + 开场段回放）
  ├─► 「在你离开期间发生了…」回放剧 UI（滚动/折叠，见 06）
  │
[在线运行]
  │   动作 Feed/Play/… ───────► append(ACTION_*)
  │   EventEngine 在线随机事件 ─► append(RANDOM_EVENT)
  │   FSM 状态切换 ───────────► append(STATE_CHANGE)
  ▼
[SessionLog.append(...)]                  ← 追加进同一份时间线
  ├─► 会话回顾（§4：本会话统计 / 时间线，只读不回写状态）
  │
[退出进程]
  │   SessionLog 内存清空（不写 SP、不落盘）
  │   PetStore 快照照常保存（唯一持久化，见 01 §9）
  ▼
[下次启动] 以新一次 settle(now) 重新开场（回到顶部）
```

## 7. 接口草案

```
enum class EventLogType { ACTION_FEED, ACTION_PLAY, ACTION_PET,
                          ACTION_HEAL, RANDOM_EVENT, STATE_CHANGE, WAKE }
// 扩展：ACTION_CLEAN / ACTION_STUDY 随 M11 / M12 追加（doc/09 §5.2/§5.3，Task.md）
// 注意：SETTLE 不再占用 EventLogType——结算聚合由 SettleEntry 表达（见下）

data class EventLog(              // 在线条目（动作 / 随机事件 / 状态切换）
  val ts: Long, val type: EventLogType, val refId: String? = null,
  val before: AttributeMap, val delta: AttributeMap,   // AttributeMap = 按注册表键存全部可变属性
  val state: PetState, val note: String? = null        // note：气泡 key、食物类型等
)

sealed interface SessionEntry            // 会话时间线统一条目（§3.1）
data class SettleEntry(                  // 开场聚合锚点（ts = settle.now）
  val ts: Long, val elapsedMs: Long,
  val totalDelta: AttributeMap,
  val endingMood: EndingMood? = null     // 结尾基调，见 03 §7.6
) : SessionEntry
data class ReplayEntry(                  // 离线回放剧开场条目（长离线才有）
  val ts: Long, val kind: OfflineKind,   // PHYSIO / SUDDEN（03 §7.6）
  val eventId: String, val bubbleId: String,
  val delta: AttributeMap, val highlight: Boolean
) : SessionEntry
data class LiveEntry(                    // 在线追加条目
  val log: EventLog
) : SessionEntry

interface SessionLog {          // domain，纯内存、进程内；不落盘（§3.1）
  fun openWith(summary: SettlementSummary)      // 启动 settle 后调用：铺开场段（回放 + SETTLE）
  fun append(log: EventLog)                     // 在线期间追加
  fun entries(): List<SessionEntry>             // 按 ts 升序的完整会话时间线
  fun liveCount(type: EventLogType): Int        // 本会话统计（供 §4 会话回顾）
  fun liveLogsSince(time: Long): List<EventLog> // 按时间窗取在线日志（供 03 §2.2 冷却判定）
}
```

> M15 换宠墓碑：`archiveCurrent()` / `switchTo(petId)` 把当前档**最终快照**复制为墓碑档、切回时反序列化为当前档（快照存取，不落日志；见 §3.3 / Task.md M15）。
