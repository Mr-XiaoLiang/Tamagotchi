# 03 · 随机事件生成系统

> 随机事件是「纯状态驱动」玩法里的**惊喜调味剂**：不引入长期记忆，只在合适的时机、合适的状态下弹出合理的互动与数值小扰动，让每天打开都不完全一样。
> 前置：阅读 [00](./00-架构与总览设计.md)、[01](./01-状态与数值系统设计.md)、[02](./02-宠物行为与AI设计.md)。

---

## 1. 事件是什么

- 一次随机事件 = **一个气泡/动作小插曲 + 可选的属性微调**（如宠物突然想散步、发现地上有食物自己吃了一口）。
- 事件有**两种运行模式**，共用同一套事件表/条件/加权定义，区别在触发节奏与数值约束：
  - **在线单发模式**：在线 FSM tick / 玩家互动后的即时小彩蛋（§2）；
  - **离线时间线回放模式**：长离线结算时，把整段离线期铺成**事件序列**（§7），玩家打开看到「在你离开期间发生了…」。
- 事件**不改变世界观常量**（无成长无记忆），只产生即时表现与数值微扰，天然不破坏「纯状态驱动」主线。

## 2. 事件触发算法

### 2.1 触发时机（三类）

| 类别 | 触发点 | 说明 |
|---|---|---|
| 在线单发 | 在线 FSM tick / 玩家互动后（小概率） | 陪伴中的小彩蛋 |
| 离线时间线回放 | 长离线 `settle(now)` 内部铺排（离线 ≥20min） | 「在你离开期间发生了…」批量事件，见 §7 |
| 迎接反馈 | 结算完成后、渲染主屏前（一次性） | 语气基调来自时间线结尾事件，见 04 §5 |

### 2.2 候选判定流程

```
fun rollEvent(context: EventContext): PetEvent? {
  // context = 当前快照 + traits/可变属性 + 时段 + 离线时长 + 冷却表 + 最近事件
  val candidates = EventTable
     .where { it.condition(context) }        // 前置条件过滤（状态/时段/数值/性格）
     .filter  { it.cooldownPassed(context) } // 冷却通过
  if (candidates.isEmpty) return null

  // 概率加权：每个候选按权重参与抽签；再乘时段权重修正
  return weightedPick(candidates, context.timeSlotWeight(it))
}
```

### 2.3 在线事件的节奏与上限（防刷）

- **在线事件冷却**：两次在线随机事件间隔至少 5~10 分钟（随机值）。
- **结算时间线不占在线冷却**：离线事件的节奏与条数由 §7 单独约束（净值守恒 + 条数封顶），与在线冷却互不干扰。
- **触发上限**：每个事件 id 有「日触发上限」与「全局间隔」，防止同一事件连续刷屏。
- 全局概率低，默认期望约「每 15~30 分钟一次在线彩蛋」，属低频调味。

## 3. 事件表结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一，如 `found_food` |
| `condition` | (EventContext)→Bool | 前置：状态、属性段、时段、性格、冷却 |
| `weight` | int | 基础权重 |
| `effect` | (EventContext)→EventEffect | 属性变化 / FSM 状态建议 / 气泡文本 id |
| `bubbleId` | string | 气泡文案 key（多语言/性格变体） |
| `offlineRole` | enum | 离线模式角色：`PHYSIO`（骨架消耗）/ `SUDDEN`（突发扰动）/ `ONLINE_ONLY`（仅在线触发） |
| `logType` | enum | 写入事件日志的类型（见 04） |
| `cooldown` | duration | 两次同事件最小间隔（在线生效；离线节奏由 §7 间隔统一铺排） |

气泡文本设计为 **key + 参数**，如 `bubble.found_food` → 「{name}发现了{thing}！」；同一 key 可配 2~3 条候选文本按权重抽，避免重复感。

## 4. 事件示例表（初版库）

| id | 触发条件 | 效果 | 说明 |
|---|---|---|---|
| `found_food` | IDLE/WALKING 且 satiation<70 | satiation +5，EXCITED 2s | 随机觅食小惊喜 |
| `sneeze` | health<60 | 打喷嚏气泡；health -0（无损失，纯表现） | 健康下滑期的「身体信号」 |
| `curious_walk` | activity 特质高 且白天 | 自动进入 WALKING 并走远一点 | 性格化动作 |
| `yawn` | 22:00 后仍醒着 | 打哈欠 → SLEEPING | 与作息联动 |
| `beg_food` | satiation<25 | 可怜眼神气泡「我饿了…」→ 提高喂食按钮可见性 | 预告式，呼应 01 §3 预示原则 |
| `dream` | SLEEPING 中 | 睡觉时气泡「zZ…梦见好吃的」 | 睡眠期小彩蛋 |
| `mood_boost` | mood<30 且玩家抚摸后 | 后续 5 分钟 mood 恢复 +30%（限一次） | 互动正反馈 |
| `treat_hunt` | appetite 特质高 且 satiation<50 | 找到「树果」道具？→ 本期不引入道具系统，直接 satiation +8 | 预留道具扩展位 |

> 说明：上表是**初版事件库草案**；真实清单在编码期按 [04] 的日志联动与真机反馈扩充。事件表以**代码常量或 assets json** 配置，便于调参不重编译（倾向 assets json + 编译期常量默认值兜底）。

## 5. 与状态、性格、时段的联动规则

| 联动维度 | 规则 |
|---|---|
| 状态 | 多数事件仅在 IDLE/WALKING 可触发；SICK/SLEEPING 有专属事件，不互相串味 |
| 属性段 | 见上表 `condition`；低属性阶段「预告式事件」权重上调，引导玩家行动 |
| 性格(traits) | activity/affinity/appetite/curiosity 等 trait 值与可变属性加权决定事件池与权重（如 activity 低不易触发 `curious_walk`，见 02 §4.4） |
| 时段 | 夜晚事件池收窄（睡觉相关 + 哈欠），白天开放活动事件 |
| 冷却 | 全局冷却 + 单事件冷却 + 日上限（§2.3） |

## 6. 事件结果 → 日志（与 04 的接口约定）

> 写入路径统一为**内存会话日志** `SessionLog`（见 [04 §3](./04-事件日志与档案设计.md)）：
> - **在线事件**：触发时即时 `SessionLog.append(...)`（`type = RANDOM_EVENT`）——只存在于本次会话内存，退出即清空；
> - **离线回放**：settle 后由 `SessionLog.openWith(...)` 把回放剧作为**开场段**注入（逐条 ReplayEntry + 一条 SettleEntry 聚合，见 04 §7）。

每个**在线**成功触发的事件调用 `SessionLog.append(...)` 写入会话日志：
- `type = EventLogType.RANDOM_EVENT`，`refId = event.id`
- 记录触发前属性快照 + 事件后效果（delta）
- `note` 记录气泡 key（供会话回顾/UI 文案）

接口草案：

```
data class EventContext(
  val snapshot: PetSnapshot,
  val personality: Personality,
  val now: Long,
  val offlineDuration: Long?,   // 结算上下文才有
  val lastEvents: List<EventLog> // 近 N 条（供冷却判定）
)

data class PetEvent(
  val id: String, val bubble: BubbleText?,
  val stateHint: PetState?, val attrDelta: AttributeDelta, val logType: EventLogType
)
```

## 7. 离线时间线回放模式（离线结算的事件化）

> 用户决策：长离线结算不再是一次性数学扣减，而是生成「在你离开期间发生了…」的**事件序列**——每次数值消减都有过程、有时间戳、可阅读。结算契约与数值守恒在 [01 §8](./01-状态与数值系统设计.md)，本节定义生成器本身。

### 7.1 运行边界

- 仅**长离线**（≥20min，阈值见 01 §8.1）生成时间线；短离线走快速积分。
- 离线多久都**不会穷举爆炸**：事件条数有上限（§7.5），超出的时间被压缩进收尾事件。

### 7.2 事件两大类

> 骨架 = 时间线主干，负责把「自然衰减」讲成事；点缀 = 插花，制造惊喜/意外，正负都有但净值受控。

| 大类 | 角色 | 例子（初版库，待扩充） | 数值规则 |
|---|---|---|---|
| **生理消耗事件**（骨架） | 固定节奏必然发生，承载衰减 | `wait_hungry` 饿着肚子等你 / `dull_wander` 无聊游荡 / `dust_dirty` 落灰变脏 / `doze_tired` 犯困打盹 / `sleep_sound` 睡得香（夜间） | Δ = 该时间片 × [01 §6.1 速率] × trait 系数（积分；文案按档位措辞） |
| **突发扰动事件**（点缀） | 小概率插入骨架之间 | 正向：`found_leftover`(+sat) / `self_play`(+mood) / `nice_dream`(+mood) · 负向：`spooked_noise`(-mood) / `knock_bowl`(-sat) | 固定小值（±2~5），净值约束见 §7.5 |

- 同一事件按属性剩余量给不同**档位措辞**：sat 高→「啃了点剩的零嘴」；低→「肚子咕咕叫，一直等你投喂」——数值小但读起来有过程感。
- 条件/加权与在线事件**共用事件表**（§3/§4），离线池只是从可用集合里按 traits+属性段收窄。

### 7.3 铺排算法（时间片节奏）

```
1. 总预算：离线窗口 × 01 §6.1 速率 × trait 系数（跨作息分段求和）
2. 片数预算：N = clamp(floor(离线时长 / 平均间隔(traits)), 1, 48)
3. 铺排：窗口近似均分 N 片，片长乘抖动 0.8~1.2，合计校正回窗口总长（预算守恒）
4. 分片定类：
     睡眠时段(22:00~07:00，见 02 §3) → 事件池收窄为 doze/sleep_sound/nice_dream
     否则 → 先 roll 突发率(§7.4)：命中=突发事件，未命中=生理消耗事件
5. 片内抽事件：按片时刻的状态段 + traits 加权抽签（复用 §2.2 候选/加权逻辑）
6. 骨架 Δ = 片长 × 速率；突发 Δ = 事件固定小值；结算末尾统一 clamp 地板
```

### 7.4 trait 命中与间隔波动

| 参数 | 公式（建议初值，可调） | 说明 |
|---|---|---|
| 骨架平均间隔 | `base / (0.6 + 0.8×activity)`，base ≈ 50min（白天） | activity 高 → 事件更密，更像「好动地过了一天」 |
| 夜间间隔 | base × 2（≈100min） | 夜耗大降，事件稀疏 |
| 突发率 | `(0.18 + 0.25×curiosity) × temper 修正` | curiosity 高更爱自己找事 |
| 事件池偏置 | traits + 属性段参与加权（§2.2） | sat 低偏「饿」主题；health 低上调受惊/喷嚏（仅表现）；hyg 低上调弄脏 |

- 间隔抖动让时间戳不规律（如 40、67、52 分钟…），填补出一条**看起来真实**的离线时间线。

### 7.5 净值守恒与条数封顶

- **骨架守恒**：骨架事件消耗合计 ≈ 01 §6.1 预算（抖动只改分布不改总量）——保证 v2 数值平衡表不因事件化而失效。
- **突发净扰动**：每 24h 离线 \|ΣΔ突发\| ≤ 3 点；配比 正向:负向 ≈ 2:1，叠加 clamp 自然削负。
- **条数封顶**：单次离线 ≤ 48 条；触顶后剩余时长并入一条收尾事件（如 `long_wait`「后来就一直静静等你」）。
- **超长离线**（> 72h）：事件数上限下调至 24 条，回放只保关键节点，避免刷屏。

### 7.6 输出与消费（瞬态，不持久化）

```
data class OfflineEvent(
  val ts: Long,               // 事件发生时刻（回放时间轴）
  val kind: OfflineKind,      // PHYSIO / SUDDEN
  val eventId: String,        // 事件表 id
  val bubbleId: String,       // 气泡文案 key（档位措辞）
  val delta: AttributeDelta,  // 该片变化
  val highlight: Boolean      // 高光：首条 / 结尾 / |Δ| 最大
)
enum class OfflineKind { PHYSIO, SUDDEN }
enum class EndingMood { JOYFUL, GRUMBLING, NEEDY, SLEEPY, SICKLY }
```

- **写入会话日志开场段**：回放剧由 `SessionLog.openWith(summary)` 注入（[04 §3.1](./04-事件日志与档案设计.md)），成为进程内存时间线的第一段——逐条 ReplayEntry + 一条 SettleEntry 聚合。不写 SP、不落盘，进程退出即清空，无需担心条目污染持久存储；48 条封顶（§7.5）只是保证开场段不臃肿。
- **展示形态**：打开后「在你离开期间发生了…」开场，按时间顺序滚动/列表；只展开高光条目，其余折叠为「此外还有 n 件小事」——回放剧与随后的在线日志在同一条时间线上滚动（UI 接入见 06）。
- **结尾基调**：由最后 1~2 条事件推导 `EndingMood`（睡得香→JOYFUL / 饿趴→NEEDY / 受凉→SICKLY…），交给 [04 §5](./04-事件日志与档案设计.md) 决定开场语气；会话回顾按本会话日志聚合（见 [04 §4](./04-事件日志与档案设计.md)）。

### 7.7 生成器接口草案

```
data class OfflineTimeline(
  val events: List<OfflineEvent>,
  val endingMood: EndingMood
)

interface OfflineTimelineBuilder {          // domain，纯 Kotlin，可单测
  fun build(window: ClosedRange<Long>,
            startAttrs: AttributeMap,
            traits: Personality): OfflineTimeline
}
```

实现要点：以**快照时间戳为随机种子**，保证同一 `now` 重复结算得到同一时间线（幂等，见 01 §8.2）。

## 8. 扩展性：道具/成就预留（本期不做）

- `effect` 已是统一返回结构，未来可扩展 `grantItem`/`unlockAchievement` 字段，**事件系统本体无需改架构**。
- 离线时间线的骨架/突发分类同样只是事件表字段（`offlineRole: PHYSIO/SUDDEN/ONLINE_ONLY`），新增剧情不改生成器。
- 这是为「好玩」预留的轻量扩展口，不进入本期编码。
