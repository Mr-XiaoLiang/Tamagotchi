# 01 · 状态与数值系统设计

> 定义**属性目录（三类：主属性 / 可变隐藏属性 / 不可变性格特质）**、状态阈值、食物类型与数值模型、离线结算（settle）与 SharedPreferences 存储 Schema。

## 1. 属性目录（三类）与无压力原则

### 1.1 三类属性总览

| 类别 | 属性 | 是否可变 | 展示位置 | 归零后果 |
|---|---|---|---|---|
| **主属性**（三个） | `satiation` 饱腹度 / `mood` 心情度 / `health` 健康度 | 可变 | **主环进度条**（三段） | 仅为表现下限，不死亡 |
| **可变隐藏属性** | `intelligence` 智力 / `hygiene` 清洁度 | 可变 | **状态面板 + 状态图标**（主环不占位） | 无恶劣后果，只影响表现与微量数值 |
| **不可变性格特质** | 见 [02 §4](./02-宠物行为与AI设计.md)（activity / affinity / appetite / curiosity / temper / learner） | **开档骰定，不变** | 性格描述词（气泡/建档页） | —（不参与面板数值） |

原则（用户决策，**无压力模式**）：
- 所有属性**归零都不会死亡、不会背叛/出走**，也不产生任何「不可逆」后果。
- 可变属性掉到 0 只是「表现下限」——宠物用表现请求照顾，玩家回来通过动作一把拉起即可。
- 允许存在**很多**这类属性（智力、清洁度只是前两个例子），架构上用**属性注册表**（§1.3）支持低成本扩展，角色都是「影响表现/决策倾向」，而非惩罚器。
- 性格是**数值驱动的倾向**而非固定模板：宠物的行为决策（移动速度、消耗速度、心情变化速度、随机倾向）由各属性值实时加权影响，详见 [02 §4](./02-宠物行为与AI设计.md)。

### 1.2 属性定义表

| 属性 | 值域 | 语义 | 主要影响 |
|---|---|---|---|
| `satiation` 饱腹度 | 0~100 | 饿不饿 | 低→饥饿表现、心情加速衰减 |
| `mood` 心情度 | 0~100 | 开不开心 | 长期过低→SAD、健康缓慢下滑 |
| `health` 健康度 | 0~100 | 身体状态 | 低→SICK（可治愈，不致死） |
| `intelligence` 智力 | 0~100 | 学会多少互动 | 高→解锁更多互动/气泡/随机事件（正向内容，非门槛惩罚） |
| `hygiene` 清洁度 | 0~100 | 干不干净 | 低→心情衰减微升 + 状态图标「脏/挠痒」表现 |

### 1.3 属性注册表（AttributeRegistry）

为支持「类似的属性可以有很多」，属性以**注册表 + 元数据**建模，而非写死字段：

```
enum AttributeRole { PRIMARY_MAIN, MUTABLE_HIDDEN, IMMUTABLE_TRAIT }

data class AttributeMeta(
  val id: AttributeId,        // satiation / mood / health / intelligence / hygiene / activity...
  val role: AttributeRole,
  val color: ColorToken,      // 面板/图标统一配色（见 06 §配色表）
  val decayTable: RateSpec,   // 各时段衰减速率
  val floor: Int = 0,         // 表现下限（归零无恶劣后果）
  val icon: Int,              // 状态图标资源
)
```

新增属性 = 注册一条 Meta + 在面板展示配置加一行；settle/FSM 只按注册表遍历，不需要改算法结构。

## 2. 展示约定（详细见 06）

- **主属性**：主环三段进度条，实时映射 0~100，颜色固定（饱腹=琥珀 / 心情=青绿 / 健康=玫红）。
- **可变隐藏属性**：不进主环；由「状态图标」（屏上方进度条区）提示异常（如脏、初级），完整数值进**状态面板**以「列表 + 进度条 + 各自颜色」呈现。
- **不可变性格特质**：仅建档页/宠物气泡文案体现，不进面板。

---

## 3. 状态阈值分段（主属性通用）

| 分段 | 范围 | 表现 | 说明 |
|---|---|---|---|
| 充盈 GREEN | 61~100 | 图标亮、无预警 | |
| 一般 YELLOW | 31~60 | 图标微暗，偶尔叹气气泡 | 提示即将需要照顾 |
| 告急 RED | 0~30 | 图标闪动 + 预警图标 | 靠近表现下限 |

- 三主属性共用此分段；**临界事件（SAD/SICK）为组合条件**（§5），单一属性低只预警不触发。
- 隐藏属性不采用三色预警（避免压力感），低于阈值时以**单色状态图标**提示即可（如清洁度低 → 气泡暗示「想洗个澡」）。

## 4. 可变隐藏属性设计

### 4.1 智力 `intelligence`
- **来源**：「学习/教育」互动（后续功能，见 [09](./09-功能系统与扩展路线.md)）；少量随机事件（如好奇翻阅）；**不会随时间衰减**（学了就会，无压力）。
- **作用**（全部是正向解锁，无惩罚）：
  - 解锁更多互动/玩具类型与气泡文本（表现层差异）；
  - 提高随机事件池可用条目（见 [03](./03-随机事件生成系统.md)）。
- **性格联动**：学习增速受不可变特质 `learner`（聪慧/好学）影响——睿智的宠物学得快，但学得慢也不会有任何负后果。

### 4.2 清洁度 `hygiene`
- **衰减**：随时间自然下降；进食/玩耍后小幅度弄脏一点。
- **恢复**：「清洁/洗澡」动作（后续功能位，v1 预留数值与状态图标）。
- **低值影响（轻度）**：
  - `hygiene < 30` → 心情衰减 ×1.3（仅微升，不触发任何恶劣事件）；
  - 状态图标提示 + 宠物偶发「挠痒/抖毛」表现（行为修饰，见 02/07）。
- 归零：仅上述表现，不会生病、不会出走。

## 5. 主属性联动规则（温和版）

| 触发（settle / 即时检查） | 进入状态 | 属性后果 |
|---|---|---|
| `satiation < 20` | 饥饿表现（乞食气泡） | 心情衰减 ×2 |
| `mood < 20` 持续 4h+ | SAD | 健康开始缓慢下滑 |
| `health` 触底（0） | **SICK**（病恹恹表现） | 需要「喂药/治疗」动作；**无死亡、无恶化循环** |
| 治疗后健康回到 60+ 起点 | 恢复常态 | — |

> 生病是「被照顾」的内容由头，不是惩罚：SICK 状态下宠物只是更需要你，不会因此死亡或离开。

## 6. 消耗 / 恢复数值模型（建议初值 v2）

> 所有速率以「属性点 / 小时」计。性格特质乘数见 [02 §4](./02-宠物行为与AI设计.md)。

### 6.1 基础消耗速率（默认特质 ×1.0）

| 场景 | sat | mood | health | hyg | int | 备注 |
|---|---|---|---|---|---|---|
| 白昼闲逛 | -2.0/h | -1.0/h | 0 | -0.6/h | 0 | |
| 夜间（22:00~07:00） | -0.5/h | -0.3/h | 0 | -0.2/h | 0 | 夜耗大降 |
| 睡眠态 | -0.2/h | 0 | +1.0/h | -0.1/h | 0 | 睡觉回血 |
| 饥饿（sat<20） | 0 | 额外-2.0/h | 0 | — | 0 | |
| SICK 期间 | -3.0/h | -2.0/h | 0（clamp） | -0.3/h | 0 | 需治疗 |

### 6.2 恢复（动作）表

| 动作 | sat | mood | health | hyg | int | 冷却 | 备注 |
|---|---|---|---|---|---|---|---|
| 喂食（按食物类型） | +见 §7 | +见 §7 | +见 §7 | -4 | 0 | 2h | 类型差异见 §7 |
| 玩耍/互动 | 0 | +15 | +2 | -2 | +1 | 1h | 玩具变体见 [09] |
| 抚摸 | 0 | +5 | 0 | 0 | 0 | 10min | 轻互动 |
| 治疗（喂药/打针） | 0 | 0 | +40 | 0 | 0 | 仅 SICK | 治愈 SICK |
| 清洁/洗澡（预留） | 0 | +2 | 0 | +35 | 0 | 3h | 后续功能 |
| 学习/教育（预留） | -3 | +5 | 0 | 0 | +5 | 1h | 后续功能 |

### 6.3 边际收益（防「一直喂到 100」）
- 恢复类收益随当前值递减：`gain = base × (100 - current) / 100`（饱腹/心情/清洁/智力通用）。
- 隐藏属性与主属性共用该规则，避免机械刷满。

## 7. 食物类型表（无经济系统，类型驱动差异）

> 决策：**不引入货币/价格**。喂食免费，但**食物分类型**，不同类型对饱腹/心情/健康的影响不同，且与宠物口味特质（见 02 §4 `appetite` 及口味子项）匹配时加成。

| 食物 | 图标 | sat | mood | health | 口味契合加成 | 说明 |
|---|---|---|---|---|---|---|
| 树果餐 | 🍎 | +30 | +2 | +1 | 均衡 | 默认推荐 |
| 能量餐 | 🍚 | +40 | 0 | 0 | 贪吃 | 只顶饱 |
| 营养餐 | 🥦 | +20 | +1 | +8 | 清淡 | 养身向 |
| 小零食 | 🍮 | +12 | +15 | -1 | 甜口 | 哄心情用 |
| 特调糊糊 | 🥣 | +25 | +5 | +3 | 新奇 | 高智力解锁 |

规则：
- 每次「喂食」在面板选一种食物（打开食物子页选择）。
- 口味契合加成：若与宠物口味特质匹配（如贪吃→能量餐、甜口→小零食），该餐 mood/sat 额外 +10%。
- 无库存/无货币（本期）；**扩展位**：二期如需「收藏/商店」类再挂靠 [09 功能映射](./09-功能系统与扩展路线.md) 的收藏扩展，不需要改本表。

## 8. 离线结算算法（settle(now)，v3：事件化时间线）

> **v3 关键升级（用户决策）**：离线结算不再是一次性的「按时间窗积分扣减」，而是把离线期**重写为一条可阅读的事件时间线**——每一次数值消减都有剧情载体，玩家打开时看到「在你离开期间发生了…」。离线期被拆成两类事件串起来：**生理消耗事件**（骨架，负责把速率表的自然衰减"讲成事"）+ **突发扰动事件**（点缀，小概率命中、有正有负），事件触发间隔带波动，用来填补离线的时间线。生成器算法与事件库见 [03 §7](./03-随机事件生成系统.md)，本文只定义结算契约与数值守恒。

### 8.1 两档路径

| 离线时长 | 路径 | 说明 |
|---|---|---|
| < 20min（阈值可调） | **快速积分** | 沿用 §6 速率直接扣，不铺时间线（避免小题大做、开销无谓） |
| ≥ 20min | **事件化时间线** | 交给 03 §7 的 `OfflineTimelineBuilder`，把时间窗切成带剧情的序列，逐条推进 |

### 8.2 结算主流程（伪代码）

输入：`PetStore` 快照（含 `lastSettledAt`）+ `now` + 性格特质。
输出：更新后快照 + `SettlementSummary`（离线秒数、事件时间线、各属性聚合 delta、结尾基调）。

```
fun settle(now: Long): SettlementSummary {
  if (now <= lastSettledAt) return noOp

  val traits = personalityTraits(pet)                      // 见 02 §4
  val elapsed = now - lastSettledAt

  if (elapsed < MIN_TIMELINE_MS) {                         // 短离线：快速积分
    val delta = applyRates(lastSettledAt, now, traits)     // 原 §6 速率模型
    return commit(delta, timeline = null)
  }

  // —— 长离线：事件化时间线 ——
  val timeline = OfflineTimelineBuilder.build(             // 见 03 §7
      window = lastSettledAt..now,
      startAttrs = snapshot.attributes,
      traits = traits)
  val endAttrs = clampAllToFloor(applyAll(timeline.events, startAttrs))
  // 状态推进（温和，与 v2 相同）
  if (health 触底)  → SICK
  else if (mood < 20 持续) → SAD
  else if (satiation < 20) → hungry intent
  else → IDLE
  return commit(endAttrs, timeline)      // 结果经 SessionLog.openWith 铺会话开场段（见 04）；快照由 PetStore 落盘
}
```

要点：
- **数值守恒**：骨架事件的消耗总额 ≈ §6.1 速率 × trait 系数 × 离线时长（各片长的随机波动合计≈0，见 03 §7.3）；突发事件的净扰动受控，每 24h 离线 \|ΣΔ\| ≤ 3 点且正向略多——保证 v2 数值平衡表不因事件化而失效。
- **事件条数封顶**：单次离线最多 48 条事件（含骨架+突发）；更长离线压缩时间片而非无限追加，见 03 §7.5。
- **无压力落地**：结算末尾统一 clamp 地板（主属性与隐藏属性下限 0）；0 只是表现地板，SICK 不随时间恶化、无死亡路径。
- **幂等**：`lastSettledAt = now` 结算后立即落盘——快照是**唯一持久化**（见 §9）。离线回放剧是**纯派生结果**（读快照 + 以时间为种随机），重复结算同一 `now` 得到同一终态与同一开场段；会话日志不落盘，由每次启动的结算重新开场（见 04 §3.1）。

### 8.3 SettlementSummary 增补字段（对接 03/04）

```
data class SettlementSummary(
  val elapsedMs: Long,
  val totalDelta: AttributeDelta,          // 聚合（SettleEntry 只记这条，不逐事件展开，见 04 §7）
  val offlineTimeline: List<OfflineEvent>? = null,  // → 会话日志开场段 ReplayEntry，仅内存（见 04 §3.1）
  val endingMood: EndingMood? = null,      // 结尾基调 → 迎接反馈语气 / 会话回顾（04 §4 / §5）
)
```

## 9. SharedPreferences 存储 Schema（PetStore v2）

单键 JSON。`schemaVersion = 2`（v1 迁移只需补默认隐藏属性与 traits 字段）。

```
key: "pet_profile"

{
  "schemaVersion": 2,
  "petId": "PIKACHU", "petName": "皮卡丘",
  "createdAt": 1725200000000, "lastSettledAt": 1725203600000,
  "attributes": {
    "satiation": 62, "mood": 80, "health": 91,
    "intelligence": 12, "hygiene": 45
  },
  "fsmState": "WALKING",
  "pos": { "x": 0.12, "y": -0.30, "dir": 1, "frame": 2 },
  "sleep": { "isAsleep": false },
  "sadDurationHours": 2.5,
  "cooldowns": { "feed_until": 0, "play_until": 0, "pet_until": 0, "clean_until": 0, "study_until": 0 },
  "stats": { "feed": 12, "play": 8, "pet": 30, "heal": 1,
             "sick_total": 2, "days_together": 3 },
                                    // 里程碑 SP 整数计数（见 04 §3.3）：跨会话累计，动作/事件命中 +1；缺省视为 0
  "personality": {
    "seed": 20240901,
    "traits": { "activity": 0.7, "affinity": 0.9, "appetite": 0.4,
                "curiosity": 0.6, "temper": 0.8, "learner": 0.5 },
    "flavor": "sweet"                       // 口味偏好（食物类型契合）
  },                                        // 完整见 02 §4
  "plugins": { "hidden": [], "sort": ["health", "wechat", "alipay"] }
}
```

字段约定：
- 时间一律 epoch millis（UTC）；坐标归一化（-1~1）。
- `cooldowns` 存「下次可用时刻」，规则引擎判断 `now >= x`。
- 属性以注册表驱动读取，新增属性只需加字段与 Meta，不破坏结构。
- `stats` 里程碑计数（见 [04 §3.3](./04-事件日志与档案设计.md)）：**会话日志不持久化的补充位**——跨会话累计次数（喂/玩/抚/治/生病/共处天数…），动作/事件成功时 `+1`；缺省字段视为 0，只增不减（里程碑语义）。

**扩展位**：里程碑需求由上文 `stats` 计数满足即可；更丰富的历史档案（`files/archive/<petId>.json`）仍属二期评估（见 [04 §3.3](./04-事件日志与档案设计.md)）。

## 10. 动作规则（ActionRule，状态驱动面板依据）

| 动作 | 可用条件 | 效果 |
|---|---|---|
| 喂食（选食物） | `now >= feed_until` 且 `satiation < 95` | 按 §7 类型 |
| 玩耍 | `now >= play_until` 且 `mood < 90` | 主抬心情（玩具变体见 09） |
| 抚摸 | `now >= pet_until` | 轻心情 + 亲昵气泡 |
| 治疗 | `fsmState == SICK` | 治愈 + 健康 +40 |
| 清洁（预留） | `now >= clean_until` 且 `hygiene < 90` | 清洁 +35 |
| 学习（预留） | `now >= study_until` | 智力 +5 / 心情 +5 |

> 面板动作集按上下文裁剪：可执行 = 实心胶囊、只读/锁定信息位 = 空心胶囊（06 §8.3）；v1 实现范围见 [09 §3](./09-功能系统与扩展路线.md)。
