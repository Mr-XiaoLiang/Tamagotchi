# 电子宠物（拓麻歌子）手表 App 需求文档

## 1. 项目背景与设计目标
- **定位**：一款运行在 Android 11（非标准 Wear OS 圆屏手表）上的轻量级拓麻歌子养成 App，同时兼具“快速调起系统实用 App”的功能。
- **性能指标**：
    - **极致秒开**：启动时间 < 200ms（首帧快速响应）。
    - **超低资源占用**：内存占用 < 30MB，挂机或退出后 0 后台 CPU 占用。
    - **低帧率省电**：动画轮播控制在 4~6 FPS。

---

## 2. 技术选型约束（AI 开发须知）
> **致 AI 开发者 / 架构师**：请严格遵守以下技术约束，切勿引入重型框架！

1. **界面与渲染框架**：采用 **Jetpack Compose for Wear OS**。
2. **启动优化架构**：
    - 使用 `Activity` + 原生轻量 View 渲染首帧 Logo。
    - 采用分步加载机制，首帧绘制完成后动态注入（`addView`）`ComposeView`。
3. **动画渲染机制**：
    - 禁止使用重型 Transition 动画 API。
    - 使用 `Canvas.drawImage` 直接裁剪渲染 4x4 精灵图（Sprite Sheet）。
    - 动画使用 `LaunchedEffect` + `delay` 驱动，控制在 4 FPS。
4. **离线与数据计算**：
    - 绝对禁止常驻后台 Service。
    - 采用**时间差补偿算法**（根据 `currentTimeStamp - lastActiveTimeStamp` 离线推演数值变化）。

---

## 3. 核心功能需求

### 3.1 宠物属性与时间机系统
- **三大核心属性**（数值范围 0~100）：
    1. **饱腹度**：随时间自然消耗，低于 20 进入“饥饿”状态。
    2. **心情度**：随时间自然消耗，饥饿时加速消耗；可以通过互动/抚摸提升。
    3. **健康度**：饱腹或心情长期过低时触发“生病”，需要打针/吃药。
- **离线推演算法**：
    - 记录退出时的 `lastActiveTime`。
    - 再次打开时，计算离线时长，一次性扣除对应属性，并更新宠物状态（如：生病、死亡、睡觉等）。
- **系统通知（AlarmManager）**：
    - 预测宠物下一次触发“重度饥饿”或“生病”的时间，向系统注册静默/精确定时闹钟，届时发送通知提醒玩家。

### 3.2 自由行走与行为状态机（FSM）
- **状态列表**：`IDLE`（站立发呆）、`WALKING`（自由行走）、`EATING`（进食中）、`SLEEPING`（睡觉中）。
- **行走算法**：
    - 宠物在圆屏内以相对坐标 $(x, y)$ 移动。
    - **防穿模机制**：判断 $x^2 + y^2 \le R^2$（以屏幕中心为原点的圆内边界），触墙后自动改变方向（0~3：下/左/右/上）。
    - **随机决策**：行走 3~5 秒后，随机进入 `IDLE` 状态 2~4 秒，再更换方向继续行走。

### 3.3 交互与实用功能联动
- **点击触发快捷跳转**：
    - 点击宠物或界面特定区域，触发 Android 原生 `Intent`，快速调起预设的手表 App（如微信、支付宝、健康等）。
    - 须做 `try-catch` 容错，若包名不存在则弹出轻提醒。
- **属性交互按钮**：
    - 界面提供极简悬浮/边缘按钮：【喂食】、【打针/治病】、【学习/互动】。
